## 2. 必须传承的实测

1. **源码注释里不能用 `↔`（U+2194）**：`wo/no-emoji` 按码位判，箭头类字符（↔ / ⇄）一律当 emoji，lint 直接红。文案改「/」+ 括注即过。**只有源码面受约束，`.md` 不受限**。
2. **verify 加段必须做「失败传播」反向验证**，不能只看 13/13 绿：本轮在 `modules/` 下造空目录 `__probe/` → 模块图与端点分组**同时**红（`11/13`），删后回 13/13；命名段用 `schemas/index.ts` 的 `LoginRequest as LoginRequestX` 注入（tsc 仍绿、可绕过类型段）→ exit=1 + 双向报差集。**「段在跑」与「段会红」是两件事**。
3. **文档声称「已机检」的断言，必须打开脚本核实**——本轮抓到两处假的：① `verify.mjs` 规则测试段只列两个文件而 `test:rules` 已有三个（-05 扩了脚本没进门禁）；② §1 与 `rules/index.js` 头注都写「`check-workspace-deps` 会机检 `WO_RULE_NAMES`」，而脚本当时只有 A~I。后者已补 J 段。**这类「纸面防线」比明说没有更危险。**
4. **`fixtures-run.mjs` 不进 verify 的理由要守住**：它自带 dist 新鲜度门（src 比产物新即重建 `dist/`），属**构建副作用**；verify 只装「不产副作用的检查」（§2 副决策 c 同理排除 build）。别以「覆盖率」为名把它塞进去。
5. **改完 OPEN-DECISIONS 必须重算面板**：`openTotal` 是机读口径（38→41），面板与交接件的数字要同源；`qa.match` 只看 DESIGN-LAYER §3.1 的 49/417/463.9，与 done/openTotal 无关。
