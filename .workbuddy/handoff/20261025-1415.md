## 2. 必须传承的实测

1. **`detail` 必须 `?? null`，否则键会凭空消失**：`JSON.stringify` 丢弃值为 `undefined` 的键。把 `detail: detail ?? null` 改成 `detail` 后重建，`JSON.stringify(buildErrorBody(7003))` 实测输出 `{"code":7003,"message":"…"}`——**tsc 全绿**（`detail?: unknown` 允许缺席），但「三出口形状一致」已破。这类断言只能靠运行期记录守住。
2. **出站体不能 `satisfies ValidationErrorBody`**：它的 `detail` 是 `{errors[]} | null`，shared 的 `ErrorBody.detail` 是 `unknown`——`{errors[]} → unknown` 可赋值、**反向不可**。正确做法是出站体用 `ErrorBody`，管道细分形状用 `const detail: ValidationErrorBody['detail'] = { errors: … }` 定型，不需要 `as`。
3. **`not-implemented.ts` 现在零调用点**：`grep -r NotImplementedError` 只剩自身定义。文件保留（后续占位包会再用），但别因为「没人用」就删。
4. **真实 HTTP 500 怎么造（不动源码）**：临时脚本放**仓库外**（`/tmp/wo-boom-probe.cjs`），用 `Module({imports:[AppModule], controllers:[Boom]})` + `NestFactory` 起在 3101，控制器抛 `Error('boom')`，脚本内 `fetch` 取响应。两个坑：① 手工挂装饰器时 `@Get()` 的路径会被折叠成控制器根路径，`@Controller('__boom')+@Get()` 的实际路由是 `/api/v1/__boom` 而**不是** `/__boom/boom`（打错了会得 404 并误判「控制器没注册」）；② 脚本在仓库外时 `require('@nestjs/core')` 解析不到，要用 `` require(`${process.cwd()}/node_modules/@nestjs/core`) ``。
5. **别用 python 文本模式回写源文件**：会把整文件变成 CRLF，而 `.gitattributes` 锁 `eol=lf`。回写一律二进制模式 `replace(b'\r\n', b'\n')`。
6. **当前无任何端点挂 `ZodValidationPipe`**（`-01~-03` 均未挂，首个挂管道端点在 P3-041）。所以 400 校验出口**不可能**是真 HTTP——取证走「真过滤器 + 假 `ArgumentsHost`」或 jest 用例 ①，这是骨架期实况，不是绕过。
