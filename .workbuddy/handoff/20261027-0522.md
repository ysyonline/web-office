## 3. 今天实测到的坑（按杀伤力）

1. **探针没有就绪等待 → 3 秒内全红**。第一次跑 P0 直接 `fetch`，Nest 尚未监听（本机
   bootstrap 约 3 秒），stderr 只有 `ExperimentalWarning`，看起来像「服务起不来」。
   现在 P0 先轮询 health（20 秒上限，进程提前退出立即报错）。**别把启动慢误判成实现坏。**
2. **ESLint `consistent-type-imports` 会盯上 Nest 构造注入的类**。`HttpAdapterHost` / `WoDb`
   只出现在类型位置，规则要求改 `import type`；但那样 `emitDecoratorMetadata` 会退化成
   `Object`，DI 在启动时才炸。解法：`@Inject(HttpAdapterHost)` / `@Inject(WoDb)`，
   让导入成为值使用。文件里有注释，别改回去。
3. **反向对照不能用 `git checkout` 回退新文件**——它们是 untracked。本次用
   `.workbuddy/trash/` 下的临时备份恢复（已删除）。以后做反向对照：先备份，再改，再 `diff` 确认。
4. **`node:sqlite` 是 experimental**：启动 stderr 有 `ExperimentalWarning`，属预期；WAL 会
   在 `var/` 下留 `wo.db-wal` / `wo.db-shm`，都在忽略范围内。
5. **Windows 强杀语义**（V3.1 卡 §2）：`child.kill()` 不保证 JS 信号事件；⑨ 用「强杀后重开库」
   验持久性，不验优雅关闭。这次实测通过。
6. **前端未改一行**：本版的「两端」是两个 WS 客户端，不是两个 Univer 窗口；双窗口是 V3.2。
