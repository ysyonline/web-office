## 2. 必须传承的实测（本轮新踩，每条废掉一轮录制）

1. **`document.querySelector('canvas')` 拿到的不是主网格。** 页面有 3 个 canvas：公式栏 `1200x27 @(204,141)`、单元格层 `88x24 @(62,189)`、主网格 `1408x678 @(16,169)`。取第一个会把点击打到公式栏，录出「什么都没发生」。**必须取面积最大者**。`probe-web.mjs` 的 `--edit` 段用的仍是 `querySelector`（V1.2.1 时只有一个 canvas），现在跑到同一条弯路，但它的判据只要求「输入后有字」，故一直是绿的——**别据此认为那里写得对**。
2. **编辑态不能用 `[contenteditable="true"]` 是否存在来判断。** 未进编辑态时该元素也在，只是宽度为 0；进编辑态后 Univer 仍以 0 宽元素承载输入，文本绘在 canvas 上。→ 断言只能落在**结果**（回车后取值），不能落在中间态。
3. **Univer 的「选中格直接键入」符合 Excel 语义**：选中 A1 后 `insertText` 会替换原内容，不需要 F2、不需要先清空。且**编辑内容独立缓冲**——Enter 前 `getValueByA1('A1')` 仍是旧值 1。这条是天然的防伪观测点（值若在 Enter 前就变，说明有绕过编辑态的直写路径）。
4. **DPR=2 下截图每帧 40~80ms**，8fps 目标实测只有 ~6fps（59 帧 / 9.9s）。要提帧率就降 DPR 或降 quality；对慢节奏演示当前够用，别为帧率牺牲清晰度。

### 3.2 本包最大结构风险（比接口形状重要）

**把同步装配改成异步 `load()`，会直接撞碎 V1.2.1 那套「effect 不卸载 + WeakMap 复用」的前提。**

现状为什么那样写：StrictMode 双次 effect 下同步 `dispose()` 会让表格完全不出栅格（详见 `SheetHost.tsx` 头部的方案 A/B/C 对比，结论已定，不要重开）。但那条结论是针对**同步**挂载成立的。一旦 `load` 变 Promise：

- effect 里不能立刻 `mountSheet`，只能等 Promise；期间组件可能已卸载（StrictMode 的第二次 effect、HMR、将来的路由切换）；
- `WeakMap` 只能记「已建好的实例」，记不住「正在建的 Promise」——双次 effect 会并发触发两次 load，两个 Promise 回来后各建一个实例，表现为**两张表叠加**；
- 而 `dispose` 又没有可靠调用点（见 3.1 末行），拿到实例后**无法安全取消**。

三条可行方向（V2.1 定接口时就该定下一条，别留到 V2.2）：

1. **实例只建一次、数据后灌**：先按空表挂载（同步，沿用现有结构），`load` 完成后再 `setWorkbookData` 灌入。风险最小，但「载入中有空白帧」，且要核 Univer 是否支持整体替换快照。
2. **WeakMap 改存 `Promise<SheetHandle>`**：并发安全，但要给 `dispose` 一个真正可用的时机。
3. **把 SheetHost 改成 class/ref 单例 + 显式生命周期**：最干净，也最贵，等于提前做 V2.3 的装配层。

### 3.3 不许碰

`@wo/shared` 导出面（且内部不得 import Univer，规则 H，见 3.1）；`apps/server` 一行不动；不引入 Tailwind / 组件库 / 图标库 / 状态库；不新增色值字面量（`no-hardcoded-color` 会拦）。
