## 2. 必须传承的实测

1. **「可赋值」不等于「相等」**（本包唯一返工）：`ErrorBody` 与 `ErrorSchema` 的一致性断言第一版只用双向可赋值，给 `ErrorBody` 加一个**可选**字段 `traceId?` 时探针**静默通过**（多出的可选属性不破坏结构兼容）。补 `KeysEqual`（`keyof` 双向包含）后同一探针才报 TS2322。**凡断言「两份定义一致」，键集合与可赋值要分开判。**
2. **码表门禁必须比文案，不只比键**：只比键的话 `2004` 文案被改成「分享已存在（重复创建）」也绿，而这句话会直接进用户可见的 `message`。反向验证已做：改文案 → 红；删码 → 红；改常量名（结构漂移）→ 命中「解析出 0 条」防假绿。
3. **骨架包的核心证据是「零调用点」**：`grep -rn "loadConfig" apps/` 除定义文件外只命中两处注释；`NotImplementedError` 全仓恰好 2 个 `new`。**留空的三处都在类型上可见**（`Partial` / 判别联合 / `NotImplementedError`），不靠注释守。
4. **`↔`（U+2194）第二次踩**：源码注释（含 `.mjs`）里写箭头会被 `wo/no-emoji` 拦，lint 直接红；`.md` 不受限。本包因此首跑 verify 13/14。
5. **卡拦读时的正确做法是留空 + 标归属包**：D1-05/D1-11 主卡不可读，故四层矩阵取值、必填/派生键清单**一律没填**，分别标给 -04 / -02。猜一份看起来权威的取值比空着更坏。
6. **7xxx 字面量没搬家**：留在 `validation-codes.ts`（管道热点、已有单测），改用 `as const satisfies Record<string, ErrorCode>` 与 shared 联合类型绑定——写码表外的码即 tsc 报错（探针 `7001→7101` 实测 TS2322）。
