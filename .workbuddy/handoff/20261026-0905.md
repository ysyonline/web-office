## 2. 必须传承的实测（每条都真实踩过，重踩 20~40 分钟）

1. **`workerURL` 不影响「能不能渲染」，只决定公式在不在 worker 算。** preset 内部 `useWorker = !!workerSrc`：不传 → `notExecuteFormula: false`，公式在**主线程**照常计算；传了却没在 worker 侧起 `UniverSheetsCoreWorkerPreset` 才会**静默不算**。原任务卡写「必填」是误读。
2. **表格不出栅格的根因是 React StrictMode × `dispose()`，不是样式。** 现象：canvas=0 + `Attempted to synchronously unmount a root while React was already rendering`。中间试过「独立子容器 + `setTimeout(dispose, 0)`」，栅格出来了但变成 `removeChild` 未捕获异常——**只把竞态换了个位置**。最终方案：宿主节点为键的 WeakMap 复用实例、effect 不做卸载（与 Univer 官方 React 示例一致）。
3. **两个样式风险都不成立，别预先打补丁。** 全局 `* { box-sizing }` 未破坏布局；Univer 变量全是 `--univer-tw-*` / `--univer-gray-*` / `--univer-primary-*`，与自有 `--color-*` 零重叠。
4. **无头浏览器调试端口不能用 9222。** WorkBuddy 自身 Electron 占着它，`bind()` 失败后探针会连到编辑器窗口，采到一堆 `ServiceProxy` / `wbscrash` 宿主日志，给出一份**假报告**。判定依据是 `/json/version` 的 UA：真 Edge 含 `Edg/`，宿主含 `WorkBuddy/`。
5. **CSS 只引一条聚合产物** `@univerjs/preset-sheets-core/lib/index.css`（201KB，design/ui/sheets-ui 已合入）。再单独引 `@univerjs/design/lib/index.css` 会重复定义并覆盖前者。
6. **`container` 必须传 HTMLElement，不能传 id 字符串。** 字符串分支走 `getElementById`，查不到时 `createElement` 出一个游离节点且不 append——表现为「实例建成功、界面不出现」的静默失败。

### 3.2 判据陷阱（本包最重要的一条，别跳过）

`spike/formula-runtime-spike/REPORT.md` §1 的 **B1/B2 结论**：**浏览器端载入时，初算不冲缓存值**——`v` 与 `f` 并存时，载入后 1s 观察窗内缓存值逐字节保留。

推论（对抗式审查得出，必须正视）：

- 若 A3 写成 `{ v: 3, f: '=SUM(A1:A2)' }`，则「A3 显示 3」**无法证明引擎算过**——它只是把缓存值 3 显示出来。
- 即使故意写错的缓存 `v: 99`，按 B2 也**不会被自动纠正**（无脏区 → 缓存稳定保留），所以「给个错值看会不会被改对」同样不是有效断言。
- **有效做法：A3 只给 `f`，不给 `v`。** 这样 `getValue()` 的任何非 null 返回值都必须由公式引擎产生。
- 这也解释了 V1.2.3（改 A1 为 5、A3 变 7）为何不可省——只有「编辑触发重算」才能排除缓存假绿。

**仍未核实的点（开工先验，别写死）**：

1. **只有 `f` 无 `v` 时，值何时出现。** spike 记录 `LifecycleStages.Rendered ≈ 560ms` 时 `TriggerCalculationController` 启动，但那是自建插件链；preset 装配下是否同构**未验**。断言前用**轮询** `getValue()` 直到非 null（上限 3s），**不要** sleep 一个固定值。
2. `appVersion` / `locale` / `styles` 这三个顶层字段能否省略未验（顶层是 `Partial`，但 `Workbook` 构造可能读 `appVersion`）。按 spike 形态给齐最稳。
3. 若轮询超时仍为 null，先怀疑「preset 下公式插件未装配」而不是数据写错——V1.2.1 已证 `createWorkbook` 可用，故 facade 侧是通的。
