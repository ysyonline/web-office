## 2. 必须传承的实测

1. **必填键名有据，不是编的**：D1-11 卡仍拦读，但 `.workbuddy/memory/2026-10-22.md` 的 D1-11 交付记录**逐字**写了「必填 3：WO_JWT_SECRET/WO_DB_URL/WO_LICENSE_PUBLIC_KEY」；`docs/license/design.md` §3 与 openapi `/api/v1/health/ready` 段独立印证 `WO_LICENSE_PUBLIC_KEY`。**卡拦读时先去 `.workbuddy/memory/` 找当年的交付记录**——这类记录往往比卡更好用，且不用解冻。
2. **`switch (spec.kind ?? 'string')` 不会收窄 `spec.kind`**：穷尽分支里 `const never: never = spec.kind` 直接编译失败。必须先把表达式提成局部常量再 switch，`never` 检查才有意义。
3. **派生键没有 `env`**：装载器里读 `spec.env` 的函数一律收成 `ValuedConfigKey`（必填+可选的联合），靠判别联合收窄，不要 `as`。
4. **`process.exitCode = 1` 不会退 0**（推翻了上一份交接的猜想）：必填缺失与 `EADDRINUSE` 两个失败面，两种写法实测都是 exit=1。选 `process.exit(1)` 的理由是**确定性**——将来 catch 路径上有存活句柄（P3-014 连接池）时，`exitCode` 会从「退 1」变成「不退出」。**猜的失败模式必须实测，测完还要把错的说法从文档里改掉。**
5. **可选键要证明「不是死配置」**：`LOG_LEVEL=error` 起服务，日志 0 行、health 仍 200。只装进对象不喂 `NestFactory` 的话，这条观测会照出一堆 `LOG [InstanceLoader]`。
6. **空串必须当缺失**：compose/K8s 的 `- FOO=` 会产出「键在值为空」，若算已配置，必填键会带着空口令启动成功。已实测：`WO_JWT_SECRET=` → exit=1 并指名该键。
7. **编译期断言要验失败传播**：R1 删 `ServerConfig.dbUrl` → TS2322(+TS2353)；R2 键表加键接口没有 → TS2322；R3 必填键去掉 `WO_` 前缀 → TS2322。三条都还原后 tsc exit=0。
