### S3（P1）D1-09 refresh 校验链私挂契约外码对

**机读实锤**：openapi `/api/v1/auth/refresh` 声明 status = **200 / 400 / 401(example 1003)**，无 423、无 1002/1005。全库 423 仅 login 挂载。
**卡内现状**：D1-09 ② 校验链「locked → 401 + **1002** + 广播 4411」「disabled → 401 + **1005** + 广播 4411」。
**三重违反**：① 同卡 ③ 栏（1002→423、1005→403）；② D1-05 ① 全表（1002 仅 423、1005 仅 403）；③ D1-05 V-5「同码挂多 HTTP status 即 FAIL」。
**契约缺口实质**：locked 用户的 refresh 失败**在契约里没有合法出口**——1003 语义是 token 无效，与「token 有效但账号被锁」不符。
**选项**：
- a) 登记 OPEN，解冻窗口给 refresh 端点补 423/403 声明（与「带参端点补挂 400」同型先例，registry 语义已在）；
- b) 卡内改判 401+1003 + detail 细分（不动契约；但 1003 的 detail 形状契约未载，属打补丁）；
- c) 维持 401+1002/1005 并标「本卡新定」（不推荐：与 V-5 禁令正面冲突）。
**建议**：a。

### S5（P2）字符数度量单位错位

**机读**：历史记录的「D1-02 9022 / D1-03 8671 / D1-04 7783 / 最大 D1-06 10106」逐个等于 **UTF-8 字节数**（D1-02：字符 4826 = 字节 9022；D1-03：4722/8671；D1-04：4269/7783）。真实字符数区间 **3980 ~ 8644**（最大 D1-13）。
**影响**：中文卡字节 ≈ 字符 × 1.8，一页阈值实际放松约 80%；「超一页即拆卡」的判据在当前记录体系下不可信。
**建议**：纪律补「度量工具 = python `len()`（字符）」，历史记录标注字节口径，重测并记入线程段。

### S9（P2）423 出现域：契约挂载面 vs 运行时 guard 面

**建议**：D1-05 全表 423 行补同款脚注；V-2 措辞限定「契约挂载面」。

### S10（P3）D1-05 V-5 括号表述混乱

「同码挂多个 HTTP status（9001→500、9002→503 除外）」——9001/9002 本就是单 status 对，不构成「多 status 例外」。真正需要豁免的是运行时过滤器层出口（402/423 类）。
