六、版本流转协议（闭版与开版必须分开做）

阶段 A
出闸判定
逐条核 V-Gate 七条，跑门禁三连。判定结果只有三种：PASS / 条件 PASS / FAIL；「条件 PASS」必须写明条件与解除日，否则视同 FAIL。
阶段 B
闭版
打 tag、补 ANCHORS 执行记录、遗留进 OPEN-DECISIONS、重生成状态面板与本计划。遗留项无归属包即不得闭版。
阶段 C
开版
下一版首包派单（锚点预置），开工前确认外部前提。R1/R2/R3 未解除且本版依赖它，则不开版——这是唯一允许「等」的情形。
阶段 D
超期处置
超期 > 30% 时二择一：减包（低优项移补丁版）或加人。不得延期而不减范围，否则后续版本日期全部失效。
顺序不可倒：先闭版再开版，上一版遗留才是下一版的已知项；并行开版会让遗留以「反正后面会补」的形式消失——这正是纸面防线的成因。
