## ② 时序 / 状态机

**启动断言链（顺序固定，任一步失败即退出码 1 并指名失败步）**

```
main.ts 引导
  → ① loadConfig()：zod 解析环境变量
       ├─ 必填缺失 → 「[config] 缺少必填键 WO_JWT_SECRET」→ exit 1
       └─ 可选键非法 → 「[config] WO_PORT=abc 非 port」→ exit 1
  → ② 国密断言（license/design §2.5，探针 scripts/gm-crypto-probe.mjs 已固化）：
       **启动断言三级（G1 → G2 → G3，任一失败 exit 1）**：
       **编号边界注（条 J 处置 G-3，#45）**：本卡 G1~G8 为**国密断言探针体系**（本卡 ② 栏 + 探针），与 D1-13 的 G1~G3（contract-diff / 装饰器从属 / 错误码常量门禁，P3-001 §2.4）**编号无关、互不相干**；跨卡引用一律带卡号前缀（如「D1-13 G3」指错误码常量门禁、「本卡 G3」指 fixture 验签），
       G1 getHashes 含 'sm3' → G2 getCurves 含 'SM2' → G3 **fixture 验签（自洽断言）**

         **只测自洽性不测互通性**，正是 P0-1 让它假阳性的原因（Node 原生自签自验恒过，
         但与 GM/T 标准口径完全不互通）。改为**固定 fixture 验签**：用入库的
         SM2 签名三件套（公钥 + payload + 签名）断言**必须验过**；
         自签自验降级为附属冒烟。

         `WO_GM_FIXTURE_PATH` 类键（① 栏唯一注册表）。
         **v1.4 措辞诚实化（第五轮审核裁决）**：该 fixture **由本仓 `scripts/issue-license.mjs`
         经 sm-crypto 产出**，是**自签向量而非外部标准向量**——它证明的是「四口径未漂移 + 篡改必拒」
         的**自洽性**，**不能**证明与 GM/T 的互通性。**G3 与 G8 的分工必须写死**：
         **G3 承担自洽、G8 独家承担互通**。v1.3 把 fixture 称作「标准向量」会把自洽证据当互通证据，
         与 P0-1 同类（那正是 Node 原生自签自验恒过带来的假阳性）。
```

**健康检查分级（liveness 与 readiness 是两个语义，不可合并）**

| 端点 | 语义 | 检查项 | 失败行为 |
|---|---|---|---|
| `GET /api/v1/health` | liveness（进程活） | 无（进程能应答即活） | 无应答 → 编排器重启（正确行为） |
| `GET /api/v1/health/ready`（本卡新定；**契约落盘 = 2026-10-24 解冻批，OPEN 82 RESOLVED**） | readiness（依赖可用） | ① DB `SELECT 1` ② License 公钥已装载 ③（容器形态）verdaccio 离线源可达性不查——那是构建期依赖非运行期 | **503 + 9002**；**编排器不得据 readiness 重启进程**（依赖故障重启只会放大故障），只应停止接入流量 |

**失败分支与回滚点**：① 三级断言只做启动期一次性检查，不做运行期轮询（运行期 sm3 不会消失）；② readiness 检查带 3s 超时，依赖抖动时 503 但进程存活——与 9002「依赖不可用」语义一致（D1-05 ② 栏第⑥步）；③ 配置热更新**不支持**——改配置 = 重启进程（SIGTERM 优雅关闭 → 30s drain → 重启，Spec §10 序列）；④ 容器形态默认值来源 = 镜像内 ENV 基线 + compose `environment:` 覆盖；裸机形态 = systemd `EnvironmentFile=/etc/web-office.env`（0600 权限）。**两形态键名完全一致**，差异只在注入载体。

## ③ 错误码映射

| 边界 | code | HTTP | 前端呈现 | 出处 |
|---|---|---|---|---|
| readiness 探针依赖不可用 | **9002** | 503（health/ready） | D 档全屏阻断（运维面，非用户面） | registry + D1-05 ② 第⑥步 |
| 启动失败（配置/断言/DB/公钥） | —（进程退出码 1） | 无 HTTP（未监听） | —（日志指名失败步） | 本卡新定 |
| TZ/时区错误写入 | 防线 = schema.md 约定 + Code Review | — | —（结构性预防，无码可映射） | schema.md §1 |

> 本卡不新增业务错误码。启动期失败走进程退出码不走 HTTP（进程未监听时无响应方可被编排器正确判定崩溃）；运行期与配置相关的唯一新出口是 readiness 503+9002，已在 registry。
