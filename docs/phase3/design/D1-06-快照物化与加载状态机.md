## ① 接口 / 数据结构

| 项 | 定义 | 出处 |
|---|---|---|
| doc 生命周期六态 | `idle`（无内存态，仅库中有快照/增量）→ `loading`（握手加载中）→ `active`（≥1 活跃 WS 连接）→ `evictable`（连接归零且最新状态已物化）→ `evicting`（驱逐执行中）→ `rebuilding`（doc-rebuild 互斥窗口中）。**rebuilding 不是第七常态**：它复用「物化→广播→重载」管线，仅互斥语义由 D1-01 五步持有。服务重启后无任何内存态，一律从 `idle` 走加载协议 | DESIGN-LAYER §3.2 D1-06 任务书条 1 + 本卡新定（态名与语义） |
| DocRegistry | `Map<fileId, { ydoc, state, lastActiveAt, inflightMaterialize }>`（进程内单写者）；每次 UPDATE 处理与每条连接活动刷新 `lastActiveAt`；`inflightMaterialize` 供 POST /files/:id/snapshot 幂等去重（进行中→2005） | 本卡新定（依据 Spec §10 单写者约束） |
| 物化输入/输出 | 入参：fileId；事务内动作 = `SELECT max(seq) → 快照字节 = Y.encodeStateAsUpdate(ydoc) 经 gzip(6) → INSERT file_snapshots { version: maxVersion+1, base_seq, snapshot, created_by }`，**快照字节与 base_seq 同一 DB 事务提交**（先记水位线再序列化——事务边界即水位线，期间到达的 update 计入下一段增量）。物化前必须**等待重算终态事件或 ≥100ms**（无头重算 10ms 去抖，同步读值是时序假象） | openapi POST /files/:id/snapshot + ADR-001 v1.1 P0-4 + Spec §10 服务端重算行 |
| 物化前置条件（短路顺序固定） | `已物化？`（该 doc 无新 update，版本已对齐）→ `inflightMaterialize？`（去重返回 2005）→ `文件写锁可得？`（被 doc-rebuild/导入互斥持有则推迟）→ 执行 | DESIGN-LAYER 任务书条 2（短路顺序）+ 本卡新定（前两条） |
| 物化三条件（触发器） | 距上一快照 ≥30min ／ 该文件累计新 update ≥500 条 ／ 客户端显式保存点（POST /files/:id/snapshot、Command「保存」）——任一满足即物化；**禁止短空闲即物化**；三参数读 D1-11 `WO_SNAPSHOT_MAX_MB` 同源配置层（30min/500 为常量，非环境变量） | Spec §10 快照物化节奏行 + openapi server-responsibilities + 本卡新定（常量非环境变量） |
| LRU 驱逐候选判据 | `state=evictable`（连接归零 **且** 已物化——unmerged=加载点之后 yjs_updates 行数 = 0）。**连接归零但未物化的 doc 不驱逐**：驱逐 = 丢内存态，未物化增量只剩 yjs_updates 慢链重建，重启等价 kill -9 | ADR-001 v1.7 裁决 3 + 本卡新定（unmerged 判据） |
| 加载协议固定语义 | `snapshot@base_seq（file_snapshots 最大 version 行）+ updates WHERE seq > base_seq`，seq 升序投递 + 在线增量无缝衔接；重复 seq 丢弃（Yjs 差量同步天然幂等，回放 update 不改变文档状态） | openapi x-websocket handshake + Spec §10 |
| 历史快照保留 | **物化不删任何旧版本**——保留策略（N 份/天数）是 OPEN 条目，PM 定稿前任何清理实现即为抢跑 | OPEN-DECISIONS（快照保留策略条）+ Spec §10 |

## ② 时序 / 状态机

**六态迁移表（事件 × 当前态 → 次态 / 动作）**

| 事件 \ 当前态 | idle | loading | active | evictable | evicting | rebuilding |
|---|---|---|---|---|---|---|
| 首连（ticket 过） | →loading | — | — | →loading（内存态复用，走差量 sync） | →loading（驱逐未完成即回活跃，取消驱逐后段） | 拒 4409（互斥窗口内拒新连接语义，D1-01 ④） |
| LOAD+增量回放完 | — | →active | — | — | — | — |
| 末条连接关闭 | — | — | →evictable（若已物化）或留 active 等待物化触发 | — | — | — |
| 物化触发（三条件任一） | 不动作（无内存态） | 推迟至 loading 完成 | 执行物化→仍 active | 执行物化→仍 evictable | 排队 | 推迟（rebuild 结束后首物化，base_seq=0） |
| 内存水位 >80% | — | — | 选驱逐候选（不选 active） | →evicting | — | — |
| 驱逐完成 | — | — | — | — | →idle（释放 ydoc 引用，可 GC） | — |
| 驱逐失败（事务/IO 错） | — | — | — | — | 回退 evictable + 告警日志 + 退避重试（60s） | — |
| doc-rebuild（D1-01 五步） | — | — | →rebuilding（先物化现场） | →rebuilding | 排队 | ⑤ 步完成后 →idle（待首连重载，base_seq 归零） |

**加载时序（握手 2 步，openapi handshake 落行）**：`取 snapshot@base_seq → [LOAD] 帧 {version, baseSeq, snapshot(gzip+Base64)} → [SYNC_STEP1] → 客户端 [SYNC_STEP2] 差量 → 按 seq 升序投递 seq>base_seq 增量 + 在线广播流无缝衔接`。**就绪信号 = 服务端开始投递增量（收到 SYNC_STEP2）**，客户端在此之后才放开本地编辑出站——早于就绪的本地编辑属 D1-01 回放抑制范畴。重连幂等：重新换 ticket 重复 0-2；期间已物化新快照则自动获得新 version/baseSeq，旧增量无需重放。

**base_seq 事务边界（错误高发点，显式定义）**：物化事务持有该文件写锁；`BEGIN → base_seq := max(seq)（此时写锁已持有，期间到达的 update 不会进入本事务基数）→ 序列化快照 → INSERT → COMMIT`。**不存在边界增量丢失**；物化期间到达的 update 落在 base_seq 之后，进下一段增量。

**drain 与物化的关系（裁决：drain 期间不强制物化）**：SIGTERM 序列 = 拒新连接 → 广播排空 → 攒批最后一次 flush → WS close 1000（预算 WO_DRAIN_BUDGET_S=30s，P3-078）。**物化是重操作（无头重算等待 + 全量序列化 + 大事务），塞进 drain 会放大超时风险，而增量已 write-through 持久化、重启可无损重建**——物化只是 update 日志压缩，不是持久化边界；30min/500 条是节流参数不是数据丢失窗口。drain 期间到达的三条件触发一律推迟到下次启动后按 idle 触发判据执行。

## ④ 验收断言补充

| # | 断言 | 落点包 |
|---|---|---|
| V-TXN | 物化事务原子性：物化中途 kill -9 → 库中**要么有完整 {version, base_seq, snapshot} 行、要么无行**，不出现有 base_seq 无快照或反之；重启后加载协议重建成功 | P3-076 |
| V-BOUND | 并发边界：物化事务进行中持续注入 update（含恰好落在 base_seq 与 base_seq+1 的边界用例）→ 物化后回放 seq>base_seq 全部增量，重建 doc 与源 doc 哈希一致，零丢失零重复 | P3-076 / P3-077 |
| V-RATE | 节流：500 次连续微编辑（<30min）只产生 ≤1 次物化；第 501 次触发第二次物化；显式保存点立即物化 | P3-076 |
| V-KEEP | 全库 grep 快照清理/删除实现（`DELETE FROM file_snapshots` 类）零命中——保留策略未定稿前**禁止任何删除**（防 P3-076 抢跑 OPEN 待决项） | P3-076 |
| V-EVICT | LRU 驱逐互斥：active doc 永不被选中驱逐；驱逐中收到新连接 → 连接成功且内存态未被释放；驱逐失败回退 + 告警 + 退避重试可观测 | P3-080 |
| V-DRAIN | drain 期间不物化：SIGTERM 后注入三条件触发 → 30s 预算内无物化事务开始；重启后按 idle 判据补物化；drain 总时长 ≤30s | P3-078 |
