## ① 接口 / 数据结构

| 项 | 定义 | 出处 |
|---|---|---|
| 连接状态机五态 | `connecting`（ticket 换取/升级中）→ `authed`（ticket 过、角色未定）→ `view` 或 `edit`（双常态）→ `closed(reason)`。**view 与 edit 是平行双常态、非 readonly 终态**——view 可经 ROLE_UPGRADE 升 edit，edit 可经超席降级链路回 view（只换角色、连接不断） | DESIGN-LAYER §3.2 D1-08 任务书条 1 + openapi handshake |
| close 码 ↔ 状态一一对应 | 4401 未认证（ticket 无效/过期/已用、re-validate 失败）／4403 无该文件编辑权限（含 viewer 发编辑 UPDATE）／4409 License 无效/缺失/过期只读降级 + 导入互斥拒新 UPDATE 语义复用（**席位满不属本码**，见本卡 ②③ 栏与 ④ 栏 V-SEAT）／4410 同账号同文件连接 ≥3／4411 会话失效（前置 session-invalidated 帧）／4412 服务端资源上限（内存水位/单 doc 预算，**以 ADR-001 v1.7 为准——openapi 4412 描述漂移已另立 OPEN，见 D1-06 卡**） | openapi x-websocket close-codes + ADR-001 v1.7 + D1-06 ③ |
| SeatMeter（可替换接口） | `interface SeatMeter { occupy(userId, fileId): OccupyResult; release(userId, fileId): void; current(): number; peak(): number }`——TS interface 发包，MVP 默认进程内 Map 计数；**升级瞬间占席、断线宽限、去重计数全在实现内**，调用方（连接网关）不感知。**双键口径（v1.3 补，Q9/P1-12）**：签名必须带 `fileId`（原单参数 `occupy(userId)`/`release(userId)` 无法表达引用计数）；**席位去重键 = `userId`**（计数口径，同用户多文件仍计 1 席），**引用计数键 = `(userId, fileId)`**（释放口径，**同用户的最后一条 `(userId,fileId)` 引用释放才减席**）——两键分工不同：前者决定 current()，后者决定何时 release；原「同用户 3 文件 current()=1」与「断线宽限过后 release」在单参数签名下互相矛盾（断线释放会误减席） | Spec §10 优雅关闭行（可替换接口硬门槛）+ license §4-bis + ADR-001 v1.3 + **本卡 v1.3 新定**（双键口径） |
| 席位判定口径（定死，商务口径） | 席位 = 并发「编辑会话」去重用户数（user_id 去重，同用户多标签/多文件计 1 席）；**查看会话不占席**；4410 按连接数计（同账号同文件 ≥3）——**两套口径互不替代** | license §4-bis + ADR-001 v1.2 + openapi server-responsibilities |
| 60s 断线宽限归属 | 断线后 60s 内重连不重复占席（防席位闪烁）；**该 60s 数值只在本卡定义一次**——服务端接口不焊死数值，只暴露 occupy/release/current/peak 四操作。**跨卡口径交叉引用（v1.3 补，P2-6）**：本 60s 是**断线宽限**，**数值唯一源 = 本卡（D1-08）**；**它不是 D1-11 的配置键**——D1-11 ① 配置键表**无断线宽限键**（其中 `WO_REVALIDATE_INTERVAL_S = 60` 是 **WS 60s 周期 re-validate**，与本 60s **数值恰好相同但语义不同**，见 ② 栏失败分支②「两计时器独立、不得合并实现」）。**实现者禁止为实现本宽限而新增 `WO_*` 环境变量**（新增即双源：卡里一份、部署环境一份），也禁止把本 60s 读成 `WO_REVALIDATE_INTERVAL_S` 的值 | DESIGN-LAYER 任务书条 4 + **本卡 v1.3 交叉引用**（D1-11 ① 同注） |
| 上行过滤 | 服务端按角色过滤上行：viewer 仅收 AWARENESS + 下行 UPDATE 流（支撑「他人光标可见」），viewer 的 UPDATE 上行被拒（4403） | openapi handshake + Spec §10 |
| 峰值计量 | 连接建立创新高即更新 `licenses.peak_concurrent`；`GET /api/v1/license/status` 暴露 currentConcurrent/peakConcurrent；完整报表 P1 不进 MVP | license §4-bis |

## ② 时序 / 状态机

**连接生命周期时序（含 ROLE_UPGRADE 与降级链路）**

```
connecting：POST /ws/ticket（Bearer JWT → 一次性 ticket，5s 单次）
  失败（过期/已用/身份失配）→ close 4401（D1-09 ① 栏）
authed：WS 建连，客户端携 view|edit 目标角色（来自文件分享/所有者权限判定）
  ├─ 目标 edit + 满席 → 自动降级 view（提示可显示）——不拒连、不断连（Spec §10「新编辑请求的处置：转只读而非拒入」）
  ├─ 目标 edit + 有席 → edit（建连即占席——SeatMeter.occupy）
  └─ 目标 view → view（不占席）
view 常态：收下行 UPDATE/AWARENESS/CONTROL；上行仅 AWARENESS + SYNC；发 UPDATE → 4403
edit 常态：全双工；每条活动刷新 D1-06 lastActiveAt（连接级 → doc 级挂钩）
  ├─ [ROLE_UPGRADE] view→edit：服务端**判席 + 判权** → 有席**且当前有该文件编辑权限**才 ack（升级瞬间占席，无「先 edit 后补占」/「先 ack 后补验」窗口）+ 该连接改按 edit 过滤上行
  │                                          → 满席**或无编辑权限** reject（连接保持 view、不中断；提示「席位已满/无编辑权限，保持只读」——权限不足是正常交互非异常，「断连即失效」候选否决）
  ├─ 降级链路（License 失效）：既有 edit 会话不中断（走 Command 守卫 + banner），**License 无效/缺失/过期时新 edit 首连 close 4409**；**满席/超席路径无 close 码**（新 edit 首连自动降级 view、ROLE_UPGRADE 满席回 role-upgrade-reject 帧——Spec §10 定死「满席时拒绝转编辑并保持只读；超席时新编辑请求降级只读」）（v1.1 修订：原写把 4409 打在 ROLE_UPGRADE 判席上，与 Spec §10 相逆；沿革见 REVIEW-INDEX）
  └─ 会话失效（登出/锁定/禁用/吊销）：前置 [CONTROL] session-invalidated → close 4411（D1-09 失效传播矩阵四事件）
断线：60s 宽限内重连（重新换 ticket）→ 不重复占席；宽限过后 SeatMeter.release(userId, fileId)
      （60s 数值唯一源 = 本卡 ① 栏，非 D1-11 配置键，见该行交叉引用）
closed(reason)：四操作之外唯一终态；正常优雅关闭走 1000（D1-06 drain 序列）
```

**同账号多连接归属（任务书条 2 裁决）**：席位按**用户**归属（user_id 去重），不按连接——同账号第 2、3 条连接（多标签/多文件）不增席；**第 4 条同文件连接才触发 4410**（防滥用上限，踢出顺序 = 拒**新**连接、按到达顺序，既有 3 条不动）。

**失败分支与回退**：① ROLE_UPGRADE ack 后占用失败（理论不可达——occupy 与 ack 同步执行）→ 若实现层出现该态，回滚角色并按 4409 语义处理，禁止出现「已 edit 未占席」窗口；② 宽限期计时与 re-validate 计时（60s）**数值相同、语义不同**——宽限保席、re-validate 踢失效会话，两计时器独立，不得合并实现；③ drain（D1-06）期间拒新连接含 ticket 换取阶段——connecting 态直接 4401 语义拒绝。

## ③ 错误码映射

| 边界 | code | WS close | 语义 | 出处 |
|---|---|---|---|---|
| ticket 失效/re-validate 失败 | — | 4401 | 未认证（D1-09 全链路） | openapi + D1-09 |
| viewer 发编辑 UPDATE / 无权限 | — | 4403 | 无该文件编辑权限 | openapi |
| License 无效/缺失/过期（新 edit 首连） | — | 4409 | 只读降级（既有编辑不中断） | openapi close-codes + license §4-bis |
| 满席新 edit 首连 / ROLE_UPGRADE 满席 | — | **无 close 码**（降级 view / role-upgrade-reject 帧） | 转只读而非拒入——v1.1 修订：原行把这两路径映射 4409，与 ② 栏、④ 栏 V-SEAT 及 Spec §10 相逆 | Spec §10 + openapi frame-protocol/handshake |
| 同账号同文件第 4 连接 | — | 4410 | 防滥用（连接数口径） | openapi + ADR-001 v1.2 |
| 会话失效 | — | 4411 | 前置 session-invalidated 帧 | openapi + D1-09 |
| 内存水位/单 doc 预算 | — | 4412 | 资源上限（ADR-001 v1.7 双触发） | ADR-001 v1.7 |

> 本卡零新增 registry 码与 close 码；4412 描述漂移已随 2026-10-24 解冻批处置（OPEN 60 RESOLVED），不在本卡重复登记。前端呈现档位全按 D1-05 ③（4401/4411 清会话回登录、4403 toast、4409 只读 banner（限 License 语义）、4410 toast、4412 服务繁忙）；**满席/超席路径无 close 码，前端按角色降级 + 提示呈现，不走 close 通道**。

## ④ 验收断言补充

| # | 断言 | 落点包 |
|---|---|---|
| V-SEAT | 席位口径机检：同用户 3 文件各 1 edit 连接 → current()=1；第 4 用户 edit 首连满席 → 降级 view 且连接存活；已有 edit 会话全程不中断 | P3-079 |
| V-UPGRADE | ROLE_UPGRADE 时序：满席 view→edit 升级 → reject 且保持 view；空出席位后升级 → ack 且**升级瞬间 SeatMeter.occupy 可观测**（无「先 edit 后补占」窗口）；**判权用例（6-A）**：无编辑权限用户升级 → reject 且保持 view、连接存活，拒绝后发 UPDATE 仍被 4403 拦；判权在 ack 前完成（无「先 ack 后补验」窗口） | P3-079 / P3-090 |
| V-GRACE | 60s 宽限：edit 断线 → 30s 重连不重复占席（current 不变）；61s 后释放（current 减 1）——宽限与 re-validate 两计时器独立（re-validate 周期触发不释放宽限中的席位）。**多文件宽限断言（v1.3 增补，Q9）**：同用户 2 文件各 1 edit 连接（current()=1），**其中 1 文件断线超 60s → `current()` 仍为 1**（另一文件的 `(userId,fileId)` 引用仍在，按双键口径不得减席）；**两文件均断线超 60s → `current()` 减至 0**——此二用例是「引用计数键 = (userId,fileId)」的唯一可执行判据，缺它则单参数签名的回归无人察觉 | P3-079 |
| V-KICK | 4410 边界：同账号同文件第 3 连接成功、第 4 连接被拒 4410；跨文件第 4 连接**不触发** 4410（口径 = 同文件） | P3-079 |
| V-PEAK | peak_concurrent 持久化：两用户并发 edit 创新高 → licenses.peak_concurrent 更新且 /license/status 暴露一致值；进程重启后 peak 不清零 | P3-079 / P3-124 |
| V-VIEWER | viewer 过滤：viewer 收到他人 UPDATE 流与 AWARENESS（光标可见）；viewer 发 UPDATE → 4403；升级 edit 后同一连接可发 UPDATE | P3-090 / P3-092 |
