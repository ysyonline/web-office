## ② 判定顺序（短路序，定死）

```
公式格 f → ① 顶层函数名 ∈ W？
     是 → volatile 四函数（NOW/TODAY/RAND/RANDBETWEEN）？→ 静态化：v=缓存值、f 剥档案(import-static)、无角标不计 N
        → 其余 → f 保留照常（主路径），结束
  → ② ∈ 桶 III（X 内已实现 6 + RANDARRAY）？→ 冻结（剥 f + 档案 frozen-excluded + 角标 + 计 N），结束
  → ③ ∉ I（引擎未实现）？→ 桶 II 冻结（frozen-unsupported + 角标 + 计 N），结束
  → ④ ∈ 桶 I（可用区）或顶层函数集为空（纯算式）→ 差分路径：
       差分格计数第 10001 格起 → diff-limit-exceeded 冻结（超限逐格，非整文件；whitelist §3.3 规则 7），结束
       无头重算（等完成信号或 ≥100ms）→ 比对：
         数值 1e-10 相对容差 / 文本·布尔严格等 / 错误码字符串等
         一致 → f 保留同权（无角标不计 N），结束
         不一致 → 冻结（diff-mismatch + 角标 + 计 N + 档案），结束
```

**差分执行约束**：在导入任务队列内（NestJS，10MB 上限内）逐格执行；重算仅该格及依赖子图；「等完成信号或 ≥100ms」是硬约束（同步读是时序假象，探针 A2a/A2b 实证）。**短路点固定**：①→②→③→④ 顺序不可重排（W 优先于桶 III：W 内 volatile 不落桶 III 冻结而是静态化——两条路径的 snapshot 形态同、档案来源字段不同、N 计数不同）。**空函数集分支（B5 评审补，本卡新定）**：顶层函数集为空的纯算式（`=A1+B2` 类）在 whitelist §3.3 规则 1 的四分支里无归属（空集对 ∈W/∈X/∉I/∈E 全 vacuous），本卡补判「按桶 I 走差分」——引擎原生实现算术运算、确定性，差分一致即保留 f 同权；**whitelist v1.6 §3.3 规则 1 已同步落盘该分支（2026-10-22，随本卡 v1.1 落地），本句原写「待同步」已于 v1.2 回改为已闭环**。

**失败分支**：① 无头重算抛错 → 该格按差分不一致降级（diff-mismatch）+ 审计日志，**不失败整个导入任务**（错误隔离在格级；**B5 评审标注**：whitelist/plan 无对应条款，本卡新定）；② 桶判定器解析 f 失败（语法异常）→ 按桶 II 冻结处理（最保守）+ 降级说明记「公式解析失败」；③ xlsx 缓存值缺失的公式格 → 无法差分也无冻结值 → 纯空值 + 档案（f 原文、v=undefined）+ 计 N——**该条目过导出闸门时跳过值校验直接还原 f**（D1-02 ② 例外规则，两卡同步修订；v1.0 时与 D1-02「v 必填」直接矛盾，B5 评审发现并闭环），打开时交 Excel 重算兜底。
