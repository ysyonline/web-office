# 验证优先排期（Layer 0：先做出可演示物）

> 状态：v1.0 ｜ 2026-10-25 ｜ 依据：用户裁决「先验证想法，不影响验证的任务全部后置」
> 定位：本文**取代 `RELEASE-PLAN.md` 的执行顺序**，**不改其总量账**。两者分层，见 §5。
> 一句话：把「首个可见物」从 2027-03-30（295 包之后）压到 **16 人日 ≈ 3.5 周**。

## 0. 为什么必须重排（目标函数变了）

原计划不是错的，它是为另一个目标优化的：

| | 原计划（`RELEASE-PLAN.md`） | 本计划 |
|---|---|---|
| 目标函数 | **最小化返工** | **最小化首次可见时间** |
| 排序依据 | 依赖闭包（地基先行） | 最短路径（假设先行） |
| 首个用户可见物 | 2027-03-30（v0.7，前 295 包之后） | **3.5 周后** |
| 验证信创库时点 | v0.1 第 1 天（阻塞 292 包） | 需要对外承诺兼容时（Layer 2） |
| 适合阶段 | 已有客户、要交付 | **还没有人确认这东西值得做** |

两个目标函数不可兼得：依赖闭包保证「不返工」，代价就是「最慢见效」。当前阶段要的是后者，但返工必须被**限制在可接受范围**——这是 §3 三条纪律存在的理由，不是可选项。

## 1. 要验证的假设（可证伪，五条）

不写功能清单，先写假设。每条都必须能被一个演示动作证伪，否则不该排进 3.5 周。

| # | 假设 | 证伪长什么样 |
|---|---|---|
| H1 | **引擎可承载**：Univer 在浏览器栈能撑住「公式 + 样式 + 合并 + 数字格式」 | 打开后公式不重算、合并错位、样式丢失 |
| H2 | **持久化成立**：编辑→保存→刷新不丢 | 刷新后内容回退 |
| H3 | **协同成立**：两人同编不冲突、光标可见、断线可恢复 | 双端互相覆盖、光标不显示、重连丢内容 |
| H4 | **互操作成立**：真实 xlsx 进得来、出得去 | 导入后结构崩、导出文件 Excel 打不开 |
| H5 | **体感成立**：陌生人 5 分钟能自己走通 | 需要有人在旁边解释每一步 |

**明确不在本轮验证**：信创库真机兼容、等保审计、SSO、License 商业闭环、气隙安装。这些是**交付约束**，不是「想法成不成立」的前提——把它们前置，是原计划 5 个月才见效的根本原因。

## 2. 五个切片（纵向贯通，不是横向铺包）

切片 = 跨前后端的一条端到端能力。**判据一律是「演示动作」，不是「断言通过」**。

| 切片 | 目标（演示动作） | 必须按最终形状写 | 允许一次性实现 | 涉及包（最小子集） | 估时 |
|---|---|---|---|---|---|
| **S1 打开就能编** | 浏览器打开 → 看到表格 → 改一格 → 求和重算 → 合并/样式正常 | Univer 实例挂载与卸载生命周期 | 初始数据硬编码、无后端 | P3-030 骨架、P3-032 挂载、P3-031 最小 token | 2 人日 |
| **S2 刷新不丢** | 编辑 → 自动保存 → F5 → 内容与滚动位置都在 | DataSource 抽象、快照读写边界 | 单用户硬编码 token、无 RBAC/审计/软删/分页、表只建 2 张 | P3-014 两表、P3-015 一条迁移、P3-045 三端点、P3-035 最小客户端 | 3 人日 |
| **S3 两人同编** | 两个浏览器同时改同一表 → 不冲突 → 光标可见 → 断线重连不丢 | **seq 定序 / snapshot@base_seq 加载 / close 码**（改这三样等于重写） | 席位计量、内存水位、优雅关闭、多实例 | P3-070/071/072/074/075/076/077 最小路径 | 5 人日 |
| **S4 真实文件进来** | 导入一份真实业务 xlsx → 结构/合并/数字格式不崩 → 导出回 Excel 能打开 | IR 中间模型与换算边界 | 公式降级为「缓存值 + 角标」、不做差分导入 | P3-100/101/105/107/108/112 最小路径 | 4 人日 |
| **S5 给别人用** | 陌生人拿链接 → 自己登录/建表/编辑/分享，全程无旁白 | 登录态与 token 刷新边界 | 单账号、无用户管理、无 SSO | P3-040/041 最小、P3-060/062/063 最小 | 2 人日 |

**合计 16 人日 ≈ 3.5 周**（单执行者，6h/天）。原计划到同一能力需 295 包 / 约 74 工作日（5 个月）。

**已交付的 70 包不浪费**：P3-010 工作区基线、P3-011 Nest 骨架、P3-012 配置与错误码、P3-002 公式运行时 spike（11 包，headless 已验）——正好是 S2 的地基，S1 的公式行为也有既有结论可抄。

## 3. 三条不可偷懒的形状（否则不是省时间，是预支返工）

切片期的自由只在这三条之外。踩了这三条，后面不是「补齐」，是「重写」。

1. **协同协议形状**：`seq` 定序、`snapshot@base_seq` 加载、close 码语义——按 ADR-001 落。允许只实现主路径，不允许换一套简化协议。
2. **持久化边界**：业务层不经手方言 SQL，一律走 DataSource / QueryBuilder。允许先跑在 SQLite 或 PG 上，不允许把 SQLite 专有写法渗到业务代码。
3. **欠账清单强制**：每个切片结束必须写「哪个包的哪些判据没做」，登记 OPEN-DECISIONS 并带归属包。**没有欠账清单的切片算未完成**——这条对应 V6「遗留可问责」，是防「演示好看、交付欠账」的唯一闸门。

## 5. 与既有文档的关系（防双源）

| 文档 | 身份 | 本轮变化 |
|---|---|---|
| `backlog.csv` | 包级**唯一事实源** | **不变**（不重排、不改状态、不新增包） |
| `RELEASE-PLAN.md` | **Layer 2 交付层**参考（总量账 / 出闸闸门 / 风险登记） | 保留全文，执行顺序让位本文 |
| 本文 | **Layer 0/1 执行顺序**（唯一） | 新增 |
| `ANCHORS.md` | 包级锚点 | 切片期按 §2「涉及包」补锚点，未交付包标 `待派发` |

**切片完成时怎么回写包状态**（关键，防「用演示冒充交付」）：

- 该包判据**全过** → 标 `已完成`；
- 只跑了主路径、边界/测试/收口未做 → 标 `部分（切片覆盖）`，并在 OPEN 登记缺口；
- **禁止**因为「切片演示能跑」就把 7 个包一次性标完成。

## 6. 里程碑与停止条件

- 每个切片末：**能演示 + 欠账已登记**，两者缺一不算完成。
- **S5 之后必须停下来做一件事**：找一个真实用户（非自己、非同事）用 30 分钟，不提示、不代操作。
- 通过 → 进 Layer 1 产品化（账户 / 权限 / 组件库 / 错误处理），再进 Layer 2 交付化。
- 不通过 → **不加功能**，记录被证伪的具体点，重定假设。改假设比堆功能便宜一个数量级。

## 7. 「怎么制定计划」——本文遵循的五条元规则

1. **先写可证伪假设，不写功能清单**。功能清单只能证明「做完了」，假设才能回答「该不该做」。
2. **按最短路径排序，不按依赖闭包排序**。依赖闭包是为「不返工」优化的，会用「最慢见效」换「零返工」；验证期这笔交换不划算。
3. **判据必须是演示动作**。「断言通过」可以由测试自己满足，「陌生人 5 分钟走通」不能。
4. **后置项必须带激活条件**。没有激活条件的后置项，等于删除。
5. **每层出闸不借绿**。Layer 0 的演示不能证明 Layer 2 可交付；信创、审计、License 的绿只能各自跑出来。
