# 验证优先排期 v2.1（原理层：假设与纪律）

> 状态：v2.1 ｜ 2026-10-25 ｜ **本文只回答「为什么这么排」**；执行顺序一律看 `ROADMAP.md`（版本 V1~V6 / 需求 / 任务 + 每日日程）。本文不维护任何排期表。

## 0. 约束与实测

| 约束事实（已核实） | 它推翻的东西 |
|---|---|
| 单人 + AI 全栈，无前后端分工 | **「人日」这个单位**。实际产出单位是**一次会话**，不是一天 |
| 前端本体为空：`apps/web` 原仅 1 个 `index.ts`，无 Vite / React / Univer | 「2 人日接引擎」不可信——那是**从零立前端** |
| 没有第二个人 | 评审、交接类流程变成纯成本，同时失去唯一的错误拦截网 |
| 一台个人电脑，无数据库、无 Docker、无 CI 服务器 | 一切需要「环境」的方案都不可行；SQLite 与本地 `verify` 才是可用的 |

**实测**（非估算）：项目历史 34 次会话，`scripts/session-effort.py` 测得并集活跃 **33.62h**；同期已交付 70 包估时合计 **81.4h** ⇒ 换算系数 **k ≈ 0.41**，即估时为实际的约 2.4 倍；会话活跃中位 **约 1.0h**。

结论：**按会话（任务）排，不按人日排**。33.62h 含设计卡与规划工作，故 k 是上界——够用于排期，不够用于对外承诺。

## 1. 五条可证伪假设

不写功能清单，先写假设。每条必须能被一个演示动作证伪，否则不该排进验证期。

| # | 假设 | 证伪长什么样 | 由谁验证 |
|---|---|---|---|
| H1 | **引擎可承载**：Univer 在浏览器栈撑得住公式 + 样式 + 合并 + 数字格式 | 公式不重算、合并错位、样式丢失 | V1 |
| H2 | **持久化成立**：编辑 → 保存 → 刷新不丢 | 刷新后内容回退 | V2 |
| H3 | **协同成立**：两人同编不冲突、光标可见、断线可恢复 | 双端互相覆盖、光标不显示、重连丢内容 | V3 |
| H4 | **互操作成立**：真实 xlsx 进得来、出得去 | 导入后结构崩、导出文件 Excel 打不开 | V4 |
| H5 | **体感成立**：陌生人 5 分钟能自己走通 | 需要有人在旁边解释每一步 | V6 |

**明确不在本轮验证**：信创库真机兼容、等保审计、SSO、License 商业闭环、气隙安装。它们是**交付约束**，不是「想法成不成立」的前提——把它们前置，是原计划 5 个月才见效的根本原因。

## 2. 架构形状：把后端推迟到 V3

「没有前后端分工」落成一条硬规则：**能不写服务端就不写**。

| 版本 | 需要服务端 | 存储 |
|---|---|---|
| V1 能编 | 否 | 硬编码 |
| V2 能存 | 否（先） | IndexedDB 实现 `DataSource` |
| V3 能同编 | **是，一个进程** | 同进程 + SQLite 文件 |
| V4 能进出 | 否 | 同上 |
| V5 能给别人 | 是（复用 V3 进程） | 同上 |

三条配套决策：

1. **数据库用 SQLite**，不用 PG。本机无 `psql`、无 Docker、无 5432 监听；SQLite 一文件一 `require`，零安装。§3 纪律已允许。
2. **`DataSource` 接口在 V2 就先定**，IndexedDB 与 HTTP 两个实现并存。V2 因此不白做，切服务端只换实现、不动业务调用点。
3. **部署态单进程**：`apps/server` 的 Nest 骨架继续当 API + WS 宿主，生产态静态托管前端产物；dev 态 Vite 5173 + 3000。**V3 之前不新增 module。**

## 3. 三条不可偷懒的形状

任务期的自由只在这三条之外。踩了这三条，后面不是「补齐」，是「重写」。

1. **协同协议形状**：`seq` 定序、`snapshot@base_seq` 加载、close 码语义——按 ADR-001 落。允许只实现主路径，不允许换一套简化协议。
2. **持久化边界**：业务层不经手方言 SQL，一律走 `DataSource` / QueryBuilder。允许先跑 IndexedDB 或 SQLite，不允许把某一实现的专有写法渗进业务代码。
3. **欠账清单强制**：每个任务结束必须写「哪些判据没做」，带归属。**没有欠账的任务算未完成**——这是防「演示好看、交付欠账」的唯一闸门。

## 4. 流程税：停四样、留三样、加两样

单人无接手人，为交接而生的文档在验证期是纯支出。**停的是维护动作，不删文件。**

| 停 | 理由 |
|---|---|
| handoff 交接件 | 没有第二个人接手；上下文靠任务卡 + `git log` |
| `ANCHORS.md` 逐包填 | 788 包锚点是交付层资产；写一条锚点的时间够写一行代码 |
| `backlog.csv` 逐包状态回写 | 只记「本版本覆盖哪几个包」一行，不逐包改状态 |
| `RELEASE-PLAN` 重生成 | 总量账冻结在 788 包 / 881.9h，不再跟随 |

| 留 | 理由 |
|---|---|
| 每任务一次 commit | 唯一回滚点，也是 AI 失忆后的恢复点 |
| `verify` 的 lint + typecheck | 单人没有第二双眼睛，这两段是唯一自动拦截 |
| 欠账一行 | 唯一防「演示好看、交付欠账」的闸门 |

| 加 | 理由 |
|---|---|
| 任务卡（≤1 页 / 任务） | AI 的跨会话记忆载体，格式见 §5 |
| 「下次开工第一句」一行 | 每次会话结束留，因为 AI 不记得上次 |

## 5. 任务卡：单人 + AI 的真正瓶颈是规格可达性

曾经卡住的真实原因不是代码难，是某个矩阵的逐码逐列取值只在被安全策略拦读的设计卡里，AI 取不到，只能编——而编一份像样的矩阵比空着更坏（前端会照着实现）。

**团队里规格在人脑子里，AI 没有脑子。** 所以每张卡必须先做一次「规格搬运」：

```
# <任务号> <一句话目标>

## 演示动作（收口时必须当场做）
1. ...
## 规格（从设计卡 / ADR / 契约摘抄，AI 可直接用）
- ...（字段、约束、码值、协议形状逐条列，不写「见 D1-xx」）
## 允许硬编码 / 允许不做
## 不许碰（碰了是重写，不是补齐）
## 完成判据
- [ ] 演示动作全部可做
- [ ] verify 的 lint + typecheck 绿
- [ ] 欠账已写
## 下次开工第一句
<一行>
```

**硬规则：卡里出现「见 D1-xx」即视为卡未完成**——AI 读不到那张卡，等于没有规格。

## 6. 后置清单与激活条件（防永久消失）

「往后排」不等于「消失」。每一项都必须写清**什么条件下必须捡回来**。

| 后置项 | 原归属 | 激活条件 | 提前缓解（低成本） |
|---|---|---|---|
| 金仓真机契约冒烟 | 交付版 v0.1 | 对外承诺「金仓兼容」时 | `RETURNING` 方言补丁（0.5–1 人日），不阻塞任何版本 |
| 审计写入与查询 | 交付版 v0.2 / v0.6 | 首个客户 POC 或等保要求出现 | 写操作留统一中间件挂点，不实现 |
| SSO 三适配 | 交付版 v0.6 | 合同写明 SSO 要求 | 登录接口留 provider 字段 |
| 席位 / 内存水位 / 优雅关闭 | 交付版 v0.9 | 多人内测前 | close 码常量先定义 |
| License 与降级 | 交付版 v0.13 | 第一次报价前 | 验签层留接口，不实现 |
| 气隙安装 / 双架构镜像 | 交付版 v0.14 | 交付前 | 无 |
| 组件库 76 包 | 交付版 v0.4 | UI 开始重复时按用量补 | V1/V5 只取 3–5 个原子组件 |
| CI 全量门禁 | 交付版 v0.3 | 第二个人接手前 | 单人期用 `node scripts/verify.mjs` |

## 7. 停止条件

- 每个版本末：能演示 + 欠账已登记，缺一不算完成。
- **V6 之后必须停**：找一个真实用户（非自己、非同事）30 分钟，不提示、不代操作。通过才进产品化；不通过就改假设，**不加功能**。
- 技术可行只是三种验证之一：它能证明「做得出来」，不能证明「有人要」。

| ID | 风险 | 缓解 |
|---|---|---|
