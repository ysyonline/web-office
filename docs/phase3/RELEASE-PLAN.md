## 5. 版本流转协议

闭版与开版是两件事，必须分开做，且顺序不可倒。

| 阶段 | 动作 | 产出 | 阻断条件 |
|---|---|---|---|
| A 出闸判定 | 逐条核 V-Gate 七条，跑门禁三连 | 判定记录（PASS / 条件 PASS / FAIL） | 任一硬判不等价于通过；「条件 PASS」必须写明条件与解除日 |
| B 闭版 | 打 tag、写 ANCHORS 执行记录、登记遗留、重生成面板与本计划 | 版本 tag、执行记录、OPEN 条目 | 遗留无归属包即不得闭版 |
| C 开版 | 下一版首包派单（锚点已预置），开工前确认外部前提 | 派单四件套 | R1/R2/R3 未解除且该版依赖它，则不开版 |
| D 超期处置 | 超期 > 30% 时二择一：减包（移低优项至补丁版）或加人 | 变更记录 | **不得延期而不减范围**——否则后续全部版本日期失效 |

**顺序为什么不可倒**：先闭版再开版，才能保证「上一版遗留」在下一版开工前是已知项；
若并行开版，遗留会以「反正后面会补」的形式消失，这正是 P3-011 收口时发现两处纸面防线的成因。
