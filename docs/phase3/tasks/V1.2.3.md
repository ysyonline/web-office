## 2. 判据：为什么「A3 变 7」这一条要三条旁证

「改 A1 后 A3 显示 7」有三种达成方式，只看结果数字无法区分：

| 达成方式 | 是否算完成 | 排除手段 |
|---|---|---|
| 引擎被编辑事件驱动重算 | ✅ 是 | 目标形态 |
| 刷新页面后重新载入新数据 | ❌ 不算（没有编辑事件） | **未重载标记** |
| A3 被覆写成常量 7 | ❌ 不算（公式已死） | **公式前后一致断言** |

对应的三条实测旁证：

1. **未重载标记**：写入前在 `window.__woProbeMark` 打随机串，整段采样期间每轮校验。
   标记存活即页面未重载——刷新会清空 `window`，这一条不可伪造。
2. **不调重算接口**：写入只走 `setValueByA1`（facade 命令链），全程未调用任何计算触发接口。
   因此 7 只能由「写 A1」这一动作间接引发。
3. **公式未变**：`getFormulaByA1('A3')` 写前写后均为 `'=SUM(A1:A2)'`。
   若 A3 被写成常量，该断言会从 `=SUM(A1:A2)` 变为空串而失败。
   这一条是新增 `getFormulaByA1` 的唯一理由——只看 `getValue` 时「重算」与「覆写」结果完全一样。

另：V1.2.2 已证「载入不冲缓存值」，故本包观测到的 `3 → 7` 不可能是缓存修正，只能是重算。

## 3. 规格

**句柄扩展**（`apps/web/src/sheet/mount-sheet.ts`）：

| 方法 | 实现 | 说明 |
|---|---|---|
| `setValueByA1(a1, value)` | `getRange(a1).setValue(value)` | 走命令链，故触发依赖重算；**返回后不代表已算完**，调用方须轮询 |
| `getFormulaByA1(a1)` | `getRange(a1).getFormula()` | 常量格返回空串；用于把「值变了」定性为重算/覆写 |

两条口径约束：

1. **不用 `getCellMatrix()` 读、不用直接改快照写**：读写都走 facade，副作用才是引擎的真实行为。
   直接改快照不会经过命令链，计算不会触发——那会得到「改了不重算」的假结论。
2. **数据文件不动**：`demo-workbook.ts` 仍是 A1=1、A2=2（载入态），5 是运行期写入。
   把初始数据改成 5 就变成「载入即 5」，反而测不到编辑路径。

## 7. 欠账（收口时填）

1. **只验证了 facade 写值这一条路径**，未验证「双击输入 5 + 回车」的人工编辑路径是否同样触发重算。
   两者理论上同属命令链，但编辑态（尤其输入法/中文输入）走的是另一套 UI 事件，未取证。
   归属：V6 真人试用时会自然覆盖。
2. **重算延迟未量化**：采样间隔 100ms，实测首次采样即已是 7，说明延迟低于 100ms；
   精确值未测。若后续出现「改完要等一下才变」的体感问题，此处是第一个该量化的点。归属：性能线。
3. **未验证传递依赖链**：只测了一级（A1 → A3）。多级（A1 → A3 → B3）、跨表引用、
   循环引用的报错形态均未测。归属：V1.3.2 边界例。
4. **改值后的状态仍是内存态**：刷新即回 1/2/3。持久化是 V2 的事，本包不做。
