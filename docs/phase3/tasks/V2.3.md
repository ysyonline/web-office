## 2. 已拍决策

| 决策 | 选择 | 理由 |
|---|---|---|
| 滚动状态存哪 | **localStorage**（key `wo.view.<docId>`） | 视口属于设备/用户偏好，不是文档内容；同步写、pagehide 可靠；不污染快照，V3 也不应同步各自滚动位置 |

## 4. 实现方案

### 4.1 引擎句柄（`mount-sheet.ts`）

`SheetHandle` 增三项：

- `getScrollState()`：直接转出 `current.getActiveSheet().getScrollState()`。
- `applyScrollState(state)`：`univerAPI.executeCommand('sheet.command.scroll-view', { unitId, sheetId, ...state })`，返回 `Promise<boolean>`。
  换单元/首帧期间 render unit 可能尚未注册，命令返回 `false`；由装配层重试，**不能因此阻断内容显示**。
- `onScroll(listener)`：`univerAPI.addEvent(univerAPI.Event.Scroll, …)` 后现读 `getScrollState()` 通知；
  返回幂等取消函数。事件挂在 Univer **实例**上而非单元上，换单元无需重挂；
  本包没有「订阅后再换单元」的路径（订阅发生在最后一次 `replaceDoc` 之后），该结论属结构推断。

### 4.2 视口存储（新增 `view-state.ts`）

- 读写 `localStorage['wo.view.' + docId]`，值为 `{sheetViewStartRow, sheetViewStartColumn, offsetX, offsetY}`。
- 读取时逐字段校验有限非负数；损坏/缺字段一律当「没有视图状态」，**不抛错、不阻断载入**。
- 写入防抖 250ms；`pagehide` / `detach` 时同步 flush 最新值。

### 4.3 装配层（`attach-data-source.ts`）

- 只有 `load` 成功（含 `null → seed`）并 `replaceDoc` 之后，才尝试恢复视口；
  读失败时**不恢复**，保持左上角空白表。
- 恢复用重试循环（最多 30 次、每次间隔 20ms，覆盖首帧 render unit 未注册的窗口）直到命令返回 `true`
  且 `getScrollState()` 与目标一致；超限则放弃并留 `view:restore give-up` 轨迹，不影响内容。
- 恢复完成后才订阅 `onScroll` 开始持久化，避免恢复动作自己触发一次无意义的写。
- `detach` 时取消订阅并 flush。

### 4.4 演示网格

`rowCount` 24 → **200**、`columnCount` 15 → **30**，给滚动判据留出真实空间。
现有 `--assert` / `--formats` / `--boundaries` 只用到 A1:C18，不受影响。

## 5. 判据

### 5.1 `--restore`：内容 + 视口一起跨过页面生命周期

```
[恢复] OK  前置：内容已落盘（A1=42）
[恢复] OK  ① 真实滚轮后视口非零（行/列/偏移都动过）｜row=40 col=15 offset=33,14
[恢复] OK  ② 视口已写入 localStorage（防抖窗口后，逐字段相等）
[恢复] OK  ③ 重载后 A1 仍为 42（内容跨过页面生命周期）
[恢复] OK  ④ 重载后视口逐字段相等（精确像素）
[恢复] OK  ⑤ 重载后 A3 由公式算出 44（快照完整）
```

- 实际值取自 2026-10-26 组合探针：`row=40 col=15 offset=33,14`，重载后四字段逐字相等。
- ① 用**真实鼠标滚轮事件**（8×120 纵向 + 4×120 Shift 横向），不用 `applyScrollState` 造视口：
  实测程序化 `scroll-view` **不发** `Event.Scroll`，拿它造视口会让 ② 变成假绿。
- ② 必须绕过应用代码直接读 `localStorage`，证明到了存储层。
- ④ 只比 `getScrollState()` 不够——必须逐字段与 ② 读到的值比，避免「恢复到了另一处但看着像」。
- 反向对照：注释掉装配层的 `void restoreViewState()` → **④ 红**，①②③⑤ 仍绿
  （新文档路径仍订阅滚动，所以 ② 不受影响），证明 ④ 不是靠内容判据带绿。

### 5.2 `--degrade`：读失败不白屏、不覆盖原数据

写坏库记录（`doc` 改为非法 JSON）→ 重载：

```
[降级] OK  前置：库中已有可读记录 / 记录已写坏
[降级] OK  ① 载入失败但 canvas 仍在（不白屏）
[降级] OK  ② isLoaded=false 且 A1 为空（降级为空白表）
[降级] OK  ③ 读失败不恢复视口（保持左上角）
[降级] OK  ④ 读失败未触发 replace（空表是占位，不是新文档）
[降级] OK  ⑤ 自动保存保持关闭（改格后无新落盘）
[降级] OK  ⑥ 原始损坏字节未被覆盖（逐字相等）
[降级] OK  ⑦ 只出现一条预期读错误（无额外 error）
[降级] OK  ⑧ 无未捕获异常
```

- ⑤⑥ 是本包最重要的两条：少了 `loaded` 守卫，用户随手改一格就会把损坏记录替换成空文档，**数据永久丢失且界面无感**。
  实测缺守卫时写入的是空表快照（`{"id":"wo-demo-book","name":"未命名",…,"0":{"0":{"v":99}}}`），
  ⑥ 的逐字比较当场变红。
- 反向对照：删掉 `onChange` 里的 `if (!loaded) return` → **⑤⑥ 红**，①②③④⑦⑧ 仍绿。
  （卡初稿曾写「③④ 红」，实测不成立：自动保存不会触发 `replace`，也不会动视口——已按实测订正。）
- ⑦ 只看重载之后新增的日志，且只放行 `[SheetHost] 数据源读取失败` 这一条预期错误。
  另有一个坑：CDP 的 `Runtime.enable` 会**重放**页面历史 console 消息（带原始时间戳），
  上一次运行的预期错误会让本次「全程零意外 error」误红；探针按会话建立时刻过滤重放条目。

## 6. 欠账

1. 精确像素恢复依赖 `sheet.command.scroll-view` 这个内部命令 id；Univer 升级时若改名，会退化为「不恢复」而非白屏（命令返回 false，重试后放弃）。
2. `offsetX/offsetY` 只验单表、无冻结窗格；冻结场景的 `startRow` 语义（注释里写明不含冻结区）未验。
3. localStorage 按文档 id 共享：同一浏览器两个标签页会互相覆盖视口；不影响内容。
4. 保存状态 UI 反馈仍未接（V5.2）。
5. 跨设备/跨浏览器恢复视口不做——这是决策，不是欠账。
