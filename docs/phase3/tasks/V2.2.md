## 1. 换实现：只换 `Data Source` 的实现，接口一行未动

`apps/web/src/data/indexeddb-data-source.ts`（新增，替代已删的 `memory-data-source.ts`）。

三处非显然的选择：

| 选择 | 理由 |
|---|---|
| 存 **JSON 字符串**，不存结构化克隆对象 | ① `bytes` 要精确字节，`TextEncoder` 一次得；② V3 走 HTTP 必是文本，序列化边界只留一处；③ 存对象时损坏由浏览器静默修复，存文本则 `JSON.parse` 抛错、可降级 |
| 按 docId 一条 **Promise 链** 串行写 | 接口要求同 docId 并发不写坏。链上必须先 `catch` 前一次失败——否则一次失败会让该 docId 之后所有写入永久拒绝（Promise 链中毒） |
| 跨标签页用 `BroadcastChannel` **只传元数据** | 直接把文档塞进消息会形成两个真相来源；收到消息后**自己回库读**，体积也只与文档大小无关 |

`subscribe` 的三个 `origin` 现在都有真实产者：`local-save`（本端写入）、`external`（别的标签页写入，经广播 + 回库读）、`remote` 仍留给 V3。

## 2. 自动保存：三条硬约束 + 一个守卫

`apps/web/src/sheet/autosave.ts`（新增，泛型 `TDoc`，不认 Univer）。

| 约束 | 做法 | 写错的后果 |
|---|---|---|
| 节流是 **debounce + 上限** | `wait = min(debounceMs, maxWaitMs - 已等时长)` | 纯 debounce 在持续输入时永不触发；纯 throttle 会存下半句话 |
| 保存中又有改动，**最后一次必须落盘** | `drain` 循环：每轮开头清 `dirty`，保存期间新改动重新置位，循环再跑一轮 | 用「排队」会存两份中间态；漏掉复查则尾部丢失 |
| 失败必须**把 `dirty` 抬回来** | `catch` 里 `dirty = true` 再返回 | 少这一行，这次改动永久丢失且**无声无息**（用户看到「改了，刷新后没了」） |

**守卫（本包最危险的一处）**：`if (!loaded) return` 才允许通知自动保存。

空表先挂、真实数据尚未回来时，引擎自己就会发一批命令（初始化、选区、格式）。若此时自动保存生效，就会把**空表**写进库，直接覆盖用户原有数据。同理，`load` 抛错后刻意**不设** `loaded`——读失败时自动保存必须保持关闭，否则用户随手改一格就把 `null` 覆盖成空文档。

配套改动：`SheetHandle` 增 `getSnapshot()`（走 `FWorkbook.save()`，引擎唯一对外序列化口径）与 `onChange()`；**`replaceDoc` 后必须重新挂命令监听**，否则后续编辑永不触发保存，而界面完全正常。

## 3. 判据：`--persist` 九条

```
[持久化] OK  前置：新库种出演示数据（A1=1）｜A1=1
[持久化] OK  前置：种子已写入 IndexedDB｜bytes=1268
[持久化] OK  ① 编辑后自动保存（节流窗口后落盘一次）｜save:end +1｜A1=42
[持久化] OK  ② 库中记录已更新为 42｜a1.v=42 bytes=1798
[持久化] OK  ③ 重载后 A1 仍为 42（内容真的跨过页面生命周期）｜A1=42
[持久化] OK  ④ 重载后 A3 由公式算出 44（公式随内容一起存活）｜A3=44｜f="=SUM(A1:A2)"
[持久化] OK  ⑤ 相邻两次改动只落盘一次（节流真的在合并）｜save:end +1
[持久化] OK  ⑥ 重载后为最新值 44（最后一次改动必落盘）｜A1=44
[持久化] OK  ⑦ 全程无保存失败｜save:error 0 次
```

为什么每条都必要：

- **③ 必须真重载**。「A1 变成 42」只在内存里也成立（V1 就是这样）。H2 要的是「关掉再打开还在」，唯一证据是把页面整个重新载入——载入路径不经过任何内存变量。
- **② 必须绕过应用代码读库**（直接 `indexedDB.open`）。否则「存进去了」与「内存里对」无法区分。
- **④ 公式要活**。只看 A1=42 无法区分「快照完整」与「只剩常量」；A3=44 由 `=SUM(A1:A2)` 现算出来，才证明快照带回了公式定义。
- **⑤⑥ 一起看**。⑤ 单独看会被「存了但存的是旧的」骗过；⑥ 单独看会被「每敲一个字存一次」骗过。

## 5. 判据先错了一次（本卡最该记住的一段）

第一版 `--persist` 报红：`⑥ 重载后是最新值 44` 得 `A1=43`，`⑤` 得 `save:end +1`。

**不是产品错，是判据抢跑。** 实测轨迹（`C:/tmp/diag-persist3.mjs`）：

```
t1 首发编辑完成  a1=43 saves=1
t3 次发编辑完成  a1=44 saves=2 starts=1   ← 43 的落盘发生在第二次输入过程中
t4 +600ms       a1=44 saves=3 starts=2   ← 44 的落盘在此刻
```

两处修正：

1. **`waitTrace` 在第一个 `save:end` 就返回**，紧接着 `Page.reload` 把还没落盘的第二笔截断。改为 `waitSaved`：等到 `dirty=false && saving=false` 且至少新增一次落盘——即**静默**，而不是「有动静」。
2. **「两次独立编辑」不等于「快速连打」**。一次「点击 + Ctrl+Home + 输入 + 回车」实测耗时 ~750ms，远超 debounce 400ms，首笔落盘必然发生在第二次输入中途，测到 2 次是**应该的**。改为一格内相距 120ms 的两条命令。
3. 顺带发现两次 `insertText` 有竞态（第二次偶尔丢失，只进去一个字符），使判据偶发红。改用 `setValueByA1` 连打——它同样走命令链、同样触发 `onCommandExecuted`，而本子判据要验的正是「两条命令会不会被合并成一次保存」。**偶发红的判据等于没有判据。**
