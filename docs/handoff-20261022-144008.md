## 一、先纠正一个可能的误解：设计卡**不是**详细设计文档

如果下次会话把 D1-05 当成「写一份详设」来干，方向就错了。卡的定义见 `docs/phase3/DESIGN-LAYER.md` §2.1/§2.2：

| | 设计卡（D1-xx） | 详细设计文档 |
|---|---|---|
| 体量 | **一页上限**，超一页即拆卡（体量以**字符数**度量，不以行数——行数可稳定而单行膨胀） | 几十页 |
| 作用 | 把**已经散落在 ADR / Spec / plan / openapi 里的决策归集到一处**，只补真正没有人定过的空 | 描述怎么实现 |
| 内容 | 固定四栏：① 接口/数据结构 ② 时序或状态机 ③ 错误码映射 ④ 验收断言补充 | 类图、模块划分、算法、实现步骤 |
| 写法 | 每行「决策 + 出处 + 消费方」，消费方能直接照抄、不用再问 | 讲清来龙去脉 |
| 工时实测 | **≈2.5h／张**（起草 0.4h + 审查 2.0h，见 TASKS §7bis 实测构成） | 数天 |

一句话：**卡回答「这件事定成什么样」，不回答「代码怎么写」**。写在卡里的东西必须是**不可再推导的前提**（签名、码段、状态迁移、断言），能从代码里看出来的东西不写进卡。

设计层原文（§2.2 条 1）：「一页上限。超一页即拆卡，不允许长成『设计文档』——长文档没人读，等于没写。」

## 四、做卡前必须知道的坑（都是实测踩过的）

1. **`pnpm` 命令可能崩**：本机 pnpm shim 由 corepack 提供、绑定的 Node 随 nvm 指针漂移（曾落到 16/20），报 `ERR_VM_DYNAMIC_IMPORT_CALLBACK_MISSING`。**这不是代码红了**。自检一律用 `node scripts/verify.mjs`（内部 `spawnSync` 直连工具入口）。装依赖才需要 pnpm。
2. **`pnpm-lock.yaml` 是唯一依赖真相**：加依赖必须更新 lock，且版本要精确（`saveExact` 已开）。
3. **`node --test <目录>` 在 Windows 不递归 `.ts`**，只报 1 个空子测试、exit=0 的假绿；必须显式列文件。
4. **块注释里不能写 glob**：`**/` 里的 `*/` 会提前闭合注释，整个文件语法错误。
5. **`.gitignore` 对已暂存文件不生效**：要移出必须 `git rm -r --cached <path>`。
6. **卡体量看字符数**，不看行数；单行 700+ 字符也算一页内，但读不动，该拆行。
