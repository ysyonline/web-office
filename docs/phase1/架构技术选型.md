# 架构技术选型结论（Phase 1）

> 产出人：高见远（首席架构师） | 日期：2026-10-21 | 状态：待用户确认
>
> **文档定位：溯源材料，非契约。本文与 `docs/spec/Spec-web-office-v1.md`、`docs/decisions/ADR-001~003` 冲突时，一律以后两者为准。**
> 本文记录的是 Phase 1 选型当时的推理过程，其中部分结论已在 Phase 2 及后续评审中被推翻（存量过期项已就地标注「已修订」，未标注项也可能随契约演进过期——引用前请核对 Spec）。

## 1. 渲染引擎路线（核心决策）

| 方案 | 性能(10万+格) | 开发成本 | 可控性 | 协议 | 结论 |
|---|---|---|---|---|---|
| Univer OSS（Canvas 自绘引擎） | 强（官方基准：滚动 600 万格 50-60FPS） | 低 | 中高（插件+命令+Facade API） | Apache-2.0 | **推荐** |
| 完全自研 Canvas | 最强 | 极高（6-12 个月起） | 最高 | — | 否决：MVP 不可承受 |
| DOM+虚拟滚动自研 | 弱（10 万格 DOM 滚动即卡顿） | 高 | 高 | — | 否决：性能天花板低 |
| Luckysheet | 中 | 低 | 低 | MIT | 否决：2025-10 已归档停维，jQuery 时代架构 |
| Fortune-sheet（Luckysheet React 移植） | 中 | 中 | 低 | MIT | 否决：社区维护弱，无演进前景 |
| Handsontable/Jspreadsheet | 中高 | 低 | 低 | 商业收费/闭源 | 否决：商用许可费且不含公式引擎 |

推荐理由：Univer 是 Luckysheet 官方后继（同团队 DreamNum），Apache-2.0、TS、活跃（v1.0.2，17.9k star），Canvas 渲染 + 500+ 函数公式引擎开源可用，且支持 Node.js 无头模式（前后端同构计算，保证公式结果一致）。

**关键边界（已核实官方文档）**：实时协同、xlsx 导入导出、编辑历史、图表、透视表属 Univer Pro 商业版（未授权限 3 人协同/导入 1MB）。即：渲染+编辑+公式用开源核心，协同与导入导出必须自建。

## 2. 公式引擎

| 方案 | 函数覆盖 | 协议 | 结论 |
|---|---|---|---|
| Univer 内置公式引擎（随核心） | 500+，支持自定义函数、数组公式、命名区域 | Apache-2.0 | **推荐** |
| HyperFormula | ~400，依赖图+增量重算完善 | GPLv3+商业双协议 | 否决：闭源 SaaS 有 copyleft 传染风险 |
| 自研（formulajs/fast-formula-parser 拼装） | 零散 | MIT | 否决：无依赖图、无增量重算，工程量黑洞 |

## 3. 协同方案

| 方案 | 离线容忍 | 复杂度 | 协议 | 结论 |
|---|---|---|---|---|
| Yjs（CRDT）+ 自建 WebSocket 服务 | 强（天然离线合并） | 中 | MIT | **推荐** |
| ShareDB（OT） | 弱（断线丢编辑、中心单点） | 中 | MIT | 否决：离线场景硬伤 |
| Automerge | 强 | 中（WASM 重、绑定需自建） | MIT | 否决：生态绑定不如 Yjs 成熟 |

**协同与公式结合的关键架构决策**：只同步「原始输入」（单元格值/公式字符串、行列结构操作），计算值一律本地由确定性引擎重算推导——输入收敛则结果必然收敛，从根本上绕开「计算结果冲突」这一最大复杂度来源。工程路径：拦截 Univer 命令层（Command/Mutation）映射为 Yjs 操作；服务端用 Univer 无头模式做权威重算与落库快照。

## 4. 导入导出

| 库 | 能力 | 协议 | 结论 |
|---|---|---|---|
| SheetJS CE 0.20.3 | 读格式最全（含 .xls 旧格式） | Apache-2.0 | **推荐用于导入解析**。注意：npm 版冻结在 0.18.5（含 CVE），必须用 cdn.sheetjs.com tarball 锁 0.20.3 |
| ExcelJS 4.4.0 | 样式读写完整、流式、SAX 读 | MIT | **推荐用于导出**（带样式）。风险：维护不活跃（2023-10 后无正式版），锁定版本可控 |

CSV 用 PapaParse 5.4.x。导入导出与 Univer snapshot 格式的转换层需自研，工作量中等，为 Phase 2 明确工作项。

## 5. 后端栈

> **已修订（Phase 2 + 信创约束）**：本节的 Prisma 与 Redis 选型均已推翻。ORM 改 **TypeORM 0.3.x**（Prisma 官方不支持金仓/达梦/openGauss，见本文 §12.1）；数据库改 **KingbaseES V8 R6 主库 / openGauss 5.x 备选**（PostgreSQL 16 仅开发期提速用）；**Redis 移出 MVP**（单实例协同广播为进程内 `CollabBus`，Redis 待 ADR-004 多实例时引入）。以下保留原文供溯源，不作为实施依据。

| 方案 | 优势 | 劣势 | 结论 |
|---|---|---|---|
| NestJS 11（TS）+ Prisma + PostgreSQL 16 + Redis 7 | 与前端同语言；Univer 无头公式引擎可直接跑在 Node（同构重算，FastAPI/Go 均做不到） | 单语言生态 | **推荐**（ORM/DB/缓存三项已修订，见上方说明） |
| FastAPI（Python） | 开发快、AI 生态 | 双语言、无法复用 Univer 引擎 | 否决 |
| Go/Gin | 并发强 | 双语言、WebSocket 生态偏薄、开发慢 | 否决 |

WebSocket：自建 Node 协同服务（ws 8.x），Redis pub/sub 做多实例广播，MVP 单实例起步即可。账户/文件走 REST（/api/v1）。

## 6. 前端框架与状态管理

推荐 **React 18.3.x**：Univer 官方 UI 层即 React，适配最顺。状态管理不引入大型方案——表格数据模型完全由 Univer 数据层托管（必须走 Command API），应用侧状态用 zustand（轻量）+ immer 辅助。**SVG 图标锁定 lucide-react（ISC 协议，1500+ 图标），全项目统一，禁用其他图标来源。**

## 7. 可行性结论与不可行警告

- 基础交互/编辑：可行（Univer 开源核心直接覆盖）
- 公式引擎：可行（Univer 内置，Apache-2.0 无传染）
- 实时协同：**可行但有条件**——最大技术风险为 Univer Command 层到 Yjs 的映射（见风险 1）
- 导入导出：可行，转换层自研
- 不可行警告：任何「开源版 Univer 直接获得协同+xlsx 导入导出」的预期不成立（Pro 闭源）；任何「全链路纯自研」的方案在 MVP 工期下不成立

## 8. 技术约束清单（版本锚定）

Univer @univerjs/* v1.0.2（所有包必须同版本，官方强制）；React 18.3.x；TypeScript 5.x；NestJS 11.x；Prisma 6.x；PostgreSQL 16；Redis 7.x；ws 8.x；Yjs 13.6.x；SheetJS CE 0.20.3（CDN tarball）；ExcelJS 4.4.0；PapaParse 5.4.x；zustand 5.x；lucide-react（lockfile 锁定）。Node >= 22 LTS。
> **已修订标注（2026-10-24 条 Q ②）**：上表 Prisma 6.x / PostgreSQL 16 / Redis 7.x 三项已推翻——ORM 改 TypeORM 0.3.x（§12.1）、库主推金仓/openGauss、Redis 移出 MVP（§5 修订注：CollabBus 进程内，多实例广播属 ADR-004 扩容范畴）。当前有效口径以 Spec §4 技术架构表为准。

## 9. 主要风险与缓解

1. **Univer 命令层→Yjs 映射复杂度（高）**：Phase 2 第一周做技术 spike 验证 Mutation 拦截与远端回放；失败降级方案 A：自研轻量 OT（服务器定序+单元格级 LWW+结构操作串行化）；降级方案 B：评估采购 Univer Pro。**整个项目唯一 P0 级验证项，排最先。**
2. Univer 商业化边界变动（中）：锁版本 1.0.2，导入导出与协同不依赖 Pro 包。
3. ExcelJS 停滞（中）：锁 4.4.0，导入导出抽象成独立服务模块，可替换。
4. 大表渲染（低）：Univer Canvas 基准已覆盖，设单 sheet 100 万格上限 + 服务端分片加载。
5. Univer 包体大（约 1.8MB gz，低）：Preset 模式只引表格模块 + 路由级懒加载。

## 11. 补充决策（2026-10-21 与 PM 性能红线对齐后）

> **已修订（外部评审分支 E，2026-10-21 晚）**：本节第 1 条的「公式重算 < 200ms」单一断言**作废**。实测 100 万格（5 万行×20 列）单次编辑触发全量重算收敛 3.8~5.4s，该数字被击穿约 20 倍。性能断言已改为四档分立（L0/L1/L2/L2b，全表重算与编辑→增量重算时延分离），**唯一权威出处为 Spec §9 AC-05 档位明细表**；对外商务承诺口径见 `docs/performance/promise-tiering.md`。以下保留原文供溯源。

1. ~~**性能红线入 Spec 量化验收**：5 万行 × 20 列滚动不掉帧、公式重算 < 200ms~~ —— **「重算 < 200ms」已作废**（改四档分立，见上方说明）；「5 万行 × 20 列滚动不掉帧」仍有效，已落为 Spec §9 的 F-x86（≥50FPS）/F-arm（≥45FPS）两条断言。验收手段用 Playwright 帧率采样 + Univer API 读值断言（Canvas 方案不能走 DOM 查询）——该手段保留不变。
2. **xlsx 导入走后端解析**：大文件解析不阻塞主线程，由 NestJS 任务队列统一解析（限流、大小校验、版本统一），MVP 导入上限 **10MB**。
3. 排期确认：协同技术 spike（Univer 命令层 → Yjs 映射验证，1 周）排 Phase 2 首位。

## 12. 信创技术约束增补（2026-10-21 用户确认后定向补充）

### 12.1 数据库：Prisma → TypeORM，主推金仓/openGauss

- 事实：Prisma 官方不支持达梦/KingbaseES/openGauss/OceanBase，无计划支持；达梦需 npm `dmdb` 驱动，金仓/openGauss 走 PG 协议（node-postgres 大部分可用），TypeORM 社区已支持 dmdb/opengauss 方言适配。
- **结论：直接按国产库兼容设计，不做「PG 起步后切」**——ORM 改为 TypeORM（信创唯一可行路线），主推 **KingbaseES/openGauss**（PG 血统，迁移成本最低），达梦 DM8 次优先适配（Phase 2 PoC 一周验证）。开发期可用本地 PostgreSQL 提速，但 **CI 必须双跑 PG + KingbaseES 兼容用例**。
- 数据层硬约束：**禁用 PG 专有特性**（无 pgvector、JSONB 操作符降级为 JSON 字符串字段）。风险：中，工期 +1-2 周。

### 12.2 CPU/OS：x86_64 与 aarch64 为 P0，LoongArch 定为 P2

- Node 22 aarch64 官方支持，鲲鹏/飞腾无障碍。
- LoongArch：Node 官方无构建，龙芯 Loongnix 社区已提供 Node v22.16.0/v20.19.4 loongarch64 预编译包及适配 npm 仓库（loongnix.cn），版本跟进有滞后风险。**MVP 支持级别：x86_64 + aarch64（麒麟 V10/统信 UOS）为 P0，loongarch64 为 P2**（按客户硬件需求再启用）。
- Docker 策略：buildx 多架构镜像（amd64/arm64）；loongarch64 需基于 Loongnix 基础镜像单独流水线，暂不投入。

### 12.3 完全离线部署：可行，三个硬约束进 Spec

- 技术栈无运行时外联（Univer/React/Yjs 均为构建期打包）；Spec 加「**运行时网络白名单 = 空**」验收断言；字体（Noto Sans SC/JetBrains Mono）OFL 协议本地打包。
- npm 离线方案：**verdaccio 私有镜像 + pnpm lockfile + 全量 store tarball 随交付包**；国产 OS 上含原生模块的包需附带离线编译工具链或预编译产物。
- SheetJS CDN tarball 约束改为：交付前一次性入 verdaccio，客户环境零外联。

### 12.4 国密与等保：P0/P2 切分

- 关键事实：Node 原生 TLS 不支持 TLCP 国密双证书协议，**国密 HTTPS 必须在网关层终结**（Nginx+Tongsuo 或东方通 TongHS），Node 内网走标准 TLS。应用层国密用 sm-crypto（SM2 签名验签 / SM3 口令哈希）。
- **P0（等保 2.0 三级基本项）**：TLCP 网关、SM3 口令哈希加盐、登录失败锁定与口令策略、操作审计日志（含协同操作）、数据备份机制。
- **P2（按客户密评要求再上）**：密评全套、存储层 SM4 落盘加密、端到端国密通道。

### 12.5 License 离线授权（方向）

离线激活码（含机器指纹+有效期+席位数）→ 换发 SM2 签名的 License 文件 → 服务端内置公钥验签。要点：绑定机器指纹（CPU/主板序列号哈希）、License 内约束席位与到期时间、验签失败降级只读。细节 Phase 2 设计。

### 12.6 Redis：保留，协议层可平替

开源 Redis 不在信创目录，但 TongRDS/宝兰德 CacheServer 全兼容 Redis 协议。**MVP 保留 Redis 7.x（自建、内网、无外联）**，用 ioredis 标准客户端 + pub/sub 封装在协同服务内部接口后，客户强制信创目录时可零代码平替为 TongRDS。
> **已修订标注（2026-10-24 条 Q ②）**：本节「MVP 保留 Redis」与 §5 修订注「Redis 移出 MVP（CollabBus 进程内）」相逆——本节为 Phase 1 原貌，当前有效口径 = Redis 移出 MVP；多实例广播（Redis pub/sub）属 ADR-004 扩容范畴，触发条件见 OPEN-DECISIONS 对应条目。

### 12.7 原结论修订清单

1. ORM：Prisma → **TypeORM**（数据层其余设计不变）
2. 新增目标环境矩阵：x86_64/aarch64 + 麒麟 V10/统信 UOS 为 P0，loongarch64 P2
3. 新增交付形态：离线安装包（应用镜像 + verdaccio 离线源 + 字体/构建产物全内嵌）
4. 新增网关层组件（Nginx+Tongsuo，TLCP 终结点）
5. Univer/Yjs/NestJS/SheetJS/ExcelJS/lucide-react 及全部版本锚定不变——均为可离线交付的纯前端/Node 生态

风险最高两项：达梦驱动 PoC（中）、LoongArch 长期版本跟进（中，P2 已规避），均不阻塞排期。
