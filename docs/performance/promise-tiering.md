# 性能承诺分级口径（对外商务 / 招标应答）

> 版本：v1.1 | 定稿：2026-10-21 | 修订：2026-10-22（P3-002 spike 实测回填，编辑类承诺补公式密度前提）| 来源：外部评审分支 E（性能红线）PM 裁决
> 关联：Spec §9 AC-04/AC-05（档位明细 v1.1）、§10 资源预算、ADR-001 v1.8
> 定位：本文件是性能承诺的**唯一对外口径出处**；研发验收以 Spec AC-05 档位明细为准，商务话术以本文件为准，两者数字必须一致（PM 承诺不得激进于架构师可达断言）。

---

## 0. 一条根本原则

**只承诺能兑现的，把「秒开 / 秒重算 / 不卡」这类会被现场打脸的形容词，全部换成带规模限定、带余量、带测试方法的定量承诺。**

PRD 历史遗留的单一数值「重算 < 200ms」为**抢跑式承诺**，已废除：该数字在 100 万格档被实测击穿约 20 倍（首编重算 5,474ms / 二次编辑 5,422ms，二次不加速），且未区分「全表重算」与「编辑→增量重算」两类时延。

---

## 1. 两条铁律

1. 「可打开 / 可浏览 / 可局部编辑」是**全档位**都能承诺的体验。
2. 「全表瞬间重算」是**任何档位都不承诺**的能力——因为含全量重算的任意规模都做不到，且全球无一竞品敢承诺。

---

## 2. 三级承诺（按实际数据行划分，非空白行）

| 档位 | 规模边界 | 承诺行为 | 指标（P95） | 强承诺区？ |
|------|----------|----------|-------------|-----------|
| 档 1 轻量/标准 | ≤ 1 万行（约 20 万格，**常规公式密度，公式格 ≤ 5,000**） | 打开 | 首屏可见 P95 < 3s | 是 |
| 档 1 轻量/标准 | 同上 | 编辑 | 受影响单元格增量收敛 P95 < 300ms | 是（须增量化前置） |
| 档 1 轻量/标准 | 同上 | 交互 | 滚动不阻塞、输入即时上屏 | 是 |
| 档 2 大表 | 1 万 ~ 5 万行（20 万 ~ 150 万格，**公式格 ≤ 10,000**） | 打开 + 浏览 + 局部编辑 | 首屏 P95 < 3s；局部编辑收敛 P95 < 800ms | 是（仅局部） |
| 档 2b 公式密集 | 行数不限档内，**公式格 10,001 ~ 20,000** | 局部编辑 | **不设毫秒值，行为承诺**（异步重算 + 进度提示 + 不阻塞） | 仅行为承诺 |
| 档 3 超大 | > 5 万行（> 100 万格）或**公式格 > 20,000** | 异步重算 + 进度提示 + 不阻塞 | **不设毫秒值，只承诺行为** | 仅行为承诺 |

> v1.1 修订说明（2026-10-22，P3-002 spike 实测）：编辑类收敛时延实测由**全文档公式总数**线性驱动（~24ms/千公式，与行数/格数无直接关系；5k/10k/20k/50k 公式档实测中位 89/258/596/1175ms）。故编辑类承诺一律补「公式格」前提；行数档位保留（打开/浏览类承诺仍按行数，首屏与渲染由格数主导）。政企真实文档公式密度通常远低于 10% 合成最坏值，「常规公式密度」指甲方业务常态（≤5 万格中公式格占比 <25%）。

### 规模上限（硬红线，已定稿）

- **单 sheet 规模上限：100 万格**（维持 Spec §10 既有值，架构师已裁决，不向竞品 1000 万格对齐）
- 竞品 1000 万格是「云分布式多机」容量，非「信创私有化单实例 Node」可比：100 万格实测 heap 1.4GB（1.5KB/格 RSS），1000 万格单 doc ≈14GB 击穿 16GB 部署预算。
- 超限行为：明确拒绝导入 / 打开并提示拆分（对齐 Google Sheets「超出网格限制」400 错误成熟做法）。
- 1000 万格属**容量红线**（非交互红线），登记 P1 随 Worker/分片终态再评估（内存预算模型 + 分片策略一并重评）。

## 3. 承诺值留余量依据（必须写进 FAQ）

甲方问「为什么是 300ms 不是 200ms」时：

- 实测 100 万格全量重算 3.8~5.4s，按 O(n) 线性外推，1 万行（20 万格，规模 1/5）**全量**重算约 760~1080ms——已超 200ms 两倍以上。
- 300ms 承诺前提是「增量重算 + 计算渲染解耦」落地后只重算受影响依赖链。若架构不做增量改造，则连档 1 都不能写 300ms，须退回「不阻塞 + 异步」。
- 因此 300ms 是「改造后才有余量」的强承诺，兑现前不得进销售话术。
- **（v1.1 补）实测数据已闭环**：公式格 ≤5,000 档增量收敛实测中位 89ms / 单轮最差 159ms（E1，calc-latency-curve.mjs），300ms 承诺余量约 1.9 倍——已从「外推估计」升级为「实测锚定」，前提改为「公式格 ≤5,000」；公式格超限的文档自动落入档 2b/档 3 行为承诺（降级规则须在规格表显式标注）。

## 4. 竞品对标（不比对手承诺更激进）

| 竞品 | 大数据量上限 | 对「打开/重算」的公开承诺 | 本质 |
|------|------------|----------------------|------|
| 腾讯文档 | 单 sheet ≤ 150 万格；另一 FAQ 1000 万格 | 「90% 文档 2s 内打开」 | 打开≠重算，无重算 SLA |
| Google Sheets | 1000 万格 / 100MB 导入 / 18278 列 | 无重算 SLA；行业公认 >10 万行显著变慢 | 无重算承诺 |
| WPS 桌面 | 1048576 行 × 16384 列 | 宣发「SUMIFS 1.6s vs 友商 46s」等**具体函数** | 只宣发具体函数，不宣发全表重算 |
| WPS 多维表格 | 单表 50 万行 × 200 列；「百万行秒开」「编辑响应 32ms」 | 32ms 编辑响应 | **数据库型多维表，非自由公式电子表格，不可直接对标**——需主动向甲方说清 |
| Excel Online | 数万行复杂数组公式 | input lag 官方承认 | 靠手动重算兜底，无量化 SLA |

**对标结论（可直接进话术）**：

> 我们承诺的口径不弱于、也不激进于任何主流对标产品——因为所有对标产品对「全表重算」都**没有量化 SLA**，我们同样不承诺全表重算耗时；我们的承诺锚定在「打开 + 交互不阻塞」这两个所有人都敢写、可验证的维度，并叠加信创国标（T/COSOCC 015-2024：关键业务操作 ≤5s、复杂操作 ≤20s）的合规基座。

## 5. 销售物料 / 招标应答禁用语

绝对禁写（未限定规模时全是危险措辞，出现即等同虚假承诺）：

- 「重算 < 200ms」
- 「万行不卡」「百万行不卡」「海量数据流畅重算」
- 「秒级重算」「全表实时计算」「即时计算」「零延迟」
- 「任意规模实时交互」「不设上限」「无限行数」
- 「百万行瞬间打开 / 秒开」（「秒开」必须改写为「首屏可见」并挂档位）

安全替换措辞（可写）：

- 档 1 内：「≤1 万行数据档内，单次编辑响应 P95 < 300ms（附测试方法与 IO 规模界定），首屏可见 P95 < 3s」
- 档 3 内：「超大数据档采用异步重算 + 进度提示，滚动与输入不被计算阻塞」
- 通用：「首屏打开时间 P95 < 3s，对齐并优于信创关键操作 ≤5s 标准」
- 任何量化承诺后必须跟三件套：① 规模档位 ② 测试方法 ③ 余量说明，缺一不可写。

## 6. 对外规格承诺表（直接进销售 FAQ / 招标应答）

| 规模档（实际数据行） | 承诺行为 | 指标 | 余量依据 | 可否进强承诺 |
|------|------|------|------|------|
| ≤1 万行（约 20 万格，公式格 ≤5,000） | 打开 | 首屏可见 P95 <3s | 对齐腾讯「2s/90%」，留 1.5 倍 | 可 |
| ≤1 万行（公式格 ≤5,000） | 编辑 | 增量收敛 P95 <300ms | 实测中位 89ms/最差 159ms（E1 曲线），留约 1.9 倍 | 可（须增量前置） |
| ≤1 万行 | 交互 | 滚动不阻塞，输入即时上屏 | 渲染虚拟化基线 | 可 |
| 1 万~5 万行（公式格 ≤10,000） | 打开+浏览+局部编辑 | 首屏 P95<3s；局部收敛 P95<800ms | 1 万公式档实测中位 258ms（E1），留约 3 倍 | 可（仅局部） |
| 公式格 10,001~20,000 | 局部编辑 | 不设毫秒值，行为承诺（异步+进度+不阻塞） | 2 万公式档实测中位 596ms/最差 895ms，数字承诺不成立 | 仅行为承诺 |
| >5 万行 或 公式格 >20,000 | 异步重算+进度+不阻塞 | 不设毫秒值 | 实测 3.8~5.4s 为下界 | 仅行为承诺 |
| 全档位上限 | 打开/导入硬上限 | 单 sheet ≤ 100 万格（实测容量定稿，P1 再评扩容） | 信创单实例 Node 1.5KB/格 RSS 预算 | 可 |

### 三条 FAQ 免则 / 说明（必须写进底注）

1. 上述指标为「指定测试环境下（国产浏览器 + 标准硬件，见《性能基线配置表》）的 P95」，非全量最高值保证。
2. 数据行数以「非空实际数据行」计，空白行不计入；超出档位自动降级到下一档承诺，不视为违约，但**必须**在规格表显式标注该降级规则。
3. 全量重算耗时不承诺、不作为验收项；验收只测「打开 + 浏览滚动流畅性 + 档 1 局部编辑响应」。招标应答里主动把全量重算从响应表删除，避免被通测。

## 7. 与研发口径的对齐约定

| 本文件（商务） | Spec AC-05 v1.1（研发） | 结论 |
|------|------|------|
| 档 1 < 300ms（公式格 ≤5,000） | L0 交互实时档 < 200ms（公式格 ≤5,000） | PM 更保守，可达（实测 P95≈160ms） |
| 档 2 < 800ms（公式格 ≤10,000） | L1 万行实时档 < 500ms（公式格 ≤10,000） | PM 更保守，可达（实测 P95≈274ms） |
| 档 2b 行为承诺（公式 1 万~2 万） | L1b 公式密集档 行为承诺 | 口径一致 |
| 档 3 行为承诺 | L2 全量 ≤10s 异步 + 进度 / L2b 坏编辑 | 口径一致 |
| 不承诺 Worker | Worker 为 P1 终态，MVP 主线程增量 | 一致 |

> 约定：商务数字永远不得激进于研发档位表中对应档的数字；当 PM 与架构师数字不一致时，取更保守者。
